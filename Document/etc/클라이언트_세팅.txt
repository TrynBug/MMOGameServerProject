# Root모션
좋은 질문이에요. Root Motion이 그냥 "안 좋은 것"이 아니라 **특정 장르에서는 핵심 기술**이에요.

## Root Motion이 빛나는 경우

### 1. 액션 게임의 무게감 있는 동작

대표적으로 **Dark Souls, Elden Ring, Sekiro 같은 소울라이크** 게임이 Root Motion의 교과서예요.

- 공격 모션 중에 캐릭터가 **자연스럽게 앞으로 미끄러지듯 전진**
- 회피(롤링)할 때 정확한 거리만큼 이동
- 후딜레이 동안 발이 땅에 밀착되어 미끄러지지 않음

이런 게임에서는 "공격 = 정확히 1.5m 앞으로 휘두름" 같은 모션이 핵심이에요. 코드로 `position += 1.5m`를 시켜버리면 발이 미끄러져 보여요. 애니메이션이 발 움직임과 이동을 통합 제어하면 자연스럽습니다.

### 2. 컷씬/시네마틱

- 캐릭터가 정해진 경로로 정확하게 움직여야 하는 시네마틱
- NPC가 의자에 앉는 동작 (의자까지 정확히 걸어가서 정확히 앉는 위치)
- 문 열기 (정확한 위치에 손을 뻗는 모션)

코드로 좌표 맞추는 것보다 모션 디자이너가 애니메이션 자체에 위치 정보를 넣는 게 훨씬 자연스럽습니다.

### 3. 격투 게임의 특수 동작

- 던지기, 잡기 기술 (상대를 정확히 들어올려서 던지는 위치)
- 콤보의 각 단계별 정확한 이동 거리
- 회피 백스텝의 정확한 거리

격투 게임은 거리가 곧 밸런스라서, 코드가 아니라 애니메이터가 거리를 정확히 잡는 게 일반적이에요.

### 4. 사실적인 1인칭/3인칭 슈터의 일부 동작

- 엄폐물 vault (뛰어넘기)
- 사다리 오르기
- 차량 탑승

"정확히 이 지점에 손이 닿고 발이 디뎌야 하는" 동작들. 코드로 맞추기 어렵습니다.

## 당신 게임에서 Root Motion이 안 맞는 이유 (재정리)

| 항목 | 당신 게임 | Root Motion 게임 |
|---|---|---|
| 이동 방식 | 마우스 클릭, NavMesh 경로 | 캐릭터 모션이 이동을 결정 |
| 서버 동기화 | 코드가 위치 결정 | 서버도 같은 모션을 돌리거나, 클라이언트 위주 |
| 속도 변경 | `moveSpeed` 변수로 즉시 조정 | 애니메이션 재생 속도와 묶임 |
| 반응성 | 즉시 멈춤/즉시 시작 | 모션 끝까지 보장 |
| 장르 | 가벼운 hack and slash | 무게감 있는 액션 |

특히 **마우스 클릭 즉시 이동 + 서버 위치 동기화 + 즉시 정지** 같은 요구사항은 Root Motion과 정반대 방향이에요. 

## 둘을 섞어 쓰기도 함

큰 게임은 보통 둘을 섞어 써요:

- **이동**: in-place 모션 + 코드로 이동 (당신 게임 방식)
- **특수 동작**: 공격, 회피, 시네마틱 등은 Root Motion

예를 들어 World of Warcraft도 평상시 이동은 in-place지만, 일부 마운트 탑승이나 시네마틱은 Root Motion을 써요.

당신 게임도 나중에 **회피 스킬, 공격 모션**을 만들 때 부분적으로 Root Motion을 쓸 가능성이 있어요. 예를 들면:

- "백스텝 스킬": 정확히 3m 뒤로 점프하는 모션. 코드보다 애니메이션이 거리 결정.
- "돌진 공격": 검을 휘두르면서 자연스럽게 앞으로 미끄러지는 모션.

이런 거 만들 때 Animator에서 **특정 상태(state)에만 Apply Root Motion을 켜는** 식으로 부분적으로 사용할 수 있어요. (Animator의 `OnAnimatorMove` 콜백 활용)

## 결론

- Root Motion은 **"애니메이션이 이동을 책임짐"** 이라는 사상
- 당신 게임처럼 **코드/서버가 위치를 책임지는** 게임에는 안 맞음
- 하지만 **특수 동작(스킬, 회피, 시네마틱)** 만들 때 부분적으로 유용할 수 있음
- 그때그때 필요한 모션에만 켜고 끄는 방식이 일반적

Idle/Run/Walk 같은 기본 이동 애니메이션은 거의 항상 **in-place로 만들고 Root Motion 끄기**가 정석이에요. 당신이 한 선택이 정답입니다.
