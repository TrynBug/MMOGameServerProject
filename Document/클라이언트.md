# MCP
- Filesystem MCP
	- Filesystem (참고: 실제 디스크에 파일을 생성하려면 write_file을 사용해야 합니다. create_file 툴은 컨테이너 내부의 가상 파일시스템에 만드는 것입니다)
	
- Unity 프로젝트 제어 방법
  - 이 프로젝트의 `Assets/Editor/AIEditorBridge.cs`에는 에디터 제어 브릿지가 구현되어 있습니다.
  - 유니티 에디터에게 명령을 내리고 싶을 때는 `Assets/Editor/ai_command.txt` 파일을 생성하고 아래 명령어 중 하나를 작성하세요. 명령은 한 줄로 작성하며, 인자는 콜론(`:`)으로 구분합니다. 좌표는 콤마(`,`)로 구분합니다.
  - 명령 실행 결과는 `Assets/Editor/ai_command_result.txt` 파일에 작성됩니다. 첫 줄에 `OK` 또는 `ERROR`가 오고, 그 다음 줄부터 상세 내용이 옵니다. 다음 명령을 보내면 결과 파일은 덮어써집니다.
  
  - **기본 제어**
    - `PLAY`: 게임 플레이 모드 시작
    - `STOP`: 게임 플레이 모드 종료
    - `REFRESH`: 에셋 데이터베이스 리프레시 (컴파일 유도)
  
  - **컴파일 / 테스트**
    - `COMPILE_CHECK`: 스크립트를 강제 재컴파일하고 에러/경고를 결과 파일에 출력합니다. 컴파일이 비동기이므로 명령 후 잠시 대기한 뒤 결과 파일을 확인해야 합니다. `PROJECT_INFO`로 컴파일 진행 여부를 폴링할 수 있습니다.
    - `RUN_EDIT_MODE_TESTS`: 모든 EditMode 테스트를 실행하고 결과를 출력합니다.
    - `RUN_EDIT_MODE_TEST:<TestFullName>`: 특정 EditMode 테스트만 실행합니다.
  
  - **씬 조작**
    - `SCENE_DUMP`: 현재 활성 씬의 게임오브젝트 계층, 위치, 컴포넌트 목록을 출력합니다.
    - `SCENE_DUMP:<scenePath>`: 지정 씬 파일의 내용을 출력합니다. 현재 작업 중인 씬에는 영향 없습니다. (예: `SCENE_DUMP:Assets/Scenes/Main.unity`)
    - `CREATE_SCENE:<scenePath>`: 빈 씬을 생성하고 저장합니다.
    - `OPEN_SCENE:<scenePath>`: 씬을 단일 모드로 엽니다.
    - `SAVE_SCENE`: 현재 씬을 저장합니다.
  
  - **게임오브젝트 조작**
    - `CREATE_PRIMITIVE:<Type>:<name>:<x,y,z>`: 프리미티브를 생성합니다. Type은 `Cube`, `Sphere`, `Capsule`, `Cylinder`, `Plane`, `Quad` 중 하나. 좌표가 없으면 원점에 생성됩니다. (예: `CREATE_PRIMITIVE:Cube:Player:0,1,0`)
    - `CREATE_EMPTY:<name>:<x,y,z>`: 빈 게임오브젝트를 생성합니다.
    - `ADD_COMPONENT:<objectPath>:<componentTypeName>`: 게임오브젝트에 컴포넌트를 추가합니다. objectPath는 `Parent/Child/GrandChild` 형식의 씬 계층 경로입니다. 컴포넌트는 FullName(`UnityEngine.Rigidbody`) 또는 단순명(`Rigidbody`)으로 지정할 수 있습니다. 단순명 사용 시 동명 타입이 여러 어셈블리에 있으면 모호할 수 있으므로 FullName을 권장합니다.
    - `DELETE_OBJECT:<objectPath>`: 게임오브젝트를 삭제합니다.
    - `SET_POSITION:<objectPath>:<x,y,z>`: 위치를 변경합니다.
  
  - **프리팹**
    - `CREATE_PREFAB:<objectPath>:<prefabPath>`: 씬의 게임오브젝트를 프리팹으로 저장합니다. (예: `CREATE_PREFAB:Player:Assets/Prefabs/Player.prefab`)
    - `INSTANTIATE_PREFAB:<prefabPath>:<name>:<x,y,z>`: 프리팹 에셋을 씬에 인스턴스화합니다.
  
  - **Stage 빌드 / Export** (씬 → 서버 OUTPUT)
    - `BUILD_NAVMESH:<sceneName>`: 활성 씬(또는 지정 씬)의 NavMesh 를 빌드해 클라 `StreamingAssets/NavMesh` + 서버 `OUTPUT/Map/NavMesh` 양쪽에 `.bin`(+`.navmeta.json`) 출력. (메뉴 `Tools/NavMesh/Build Active Scene` 과 동일.) 인자 생략 시 활성 씬 이름 사용.
    - `EXPORT_STAGELAYOUT:<sceneName>`: 활성 씬의 배치 마커(`SpawnerMarker`/`SpawnPointMarker`/`EventAreaMarker`/`WaypointMarker`/`PropMarker`)를 스캔해 서버 레이아웃 `OUTPUT/Map/StageLayout/<씬이름>.json` 으로 export. (메뉴 `Tools/StageLayout/Export Active Scene` 과 동일.) 인자 생략 시 활성 씬 이름. ※ json 은 서버 전용 — 클라는 런타임 프리팹의 `EventAreaMarker`/`PropMarker` 를 직접 사용.
  
  - **콘솔 / 정보**
    - `GET_CONSOLE_LOGS`: 콘솔의 모든 로그(INFO/WARN/ERROR)를 출력합니다.
    - `CLEAR_CONSOLE`: 콘솔을 클리어합니다.
    - `PROJECT_INFO`: Unity 버전, 프로젝트 경로, 활성 씬, 플레이 모드 여부, 컴파일 중 여부를 출력합니다.
  
  - 코드를 새로 생성하거나 수정했다면, 유니티가 즉시 컴파일할 수 있도록 반드시 `REFRESH` 또는 `COMPILE_CHECK` 명령을 보내야 합니다. 컴파일 결과까지 확인하려면 `COMPILE_CHECK`를 사용하세요.


# 최종 목표
- 최종 목표
게임 개발을 경험해보고, 제품으로 이어질 수 있는지의 가능성을 체크하는것이 목표입니다.  
트리 오브 세이비어와의 차이점은, 현재 게임은 가벼운 hack and slash 장르로 만들 것입니다. 수많은 몬스터, 수많은 투사체, 수많은 스킬 이펙트를 어느정도까지 렉 없이 처리할 수 있는지 가능성을 보려고 합니다.  

그리고 조작감이 아주 가벼운 게임을 만드려고 합니다.  
플레이어가 캐릭터를 움직였을 때 즉시 반응해야 하며, 멈추고 싶을때 즉시 멈추어야 합니다. 스킬들의 선딜레이, 후딜레이도 거의 없어야 합니다(쿨타임은 있음). 텔레포트 등의 회피 스킬도 사용가능한경우 즉시 발동되어야 합니다.  
캐릭터가 이동하는 도중에 스킬을 사용하면, 이동도중사용가능 스킬이라면 스킬이 즉시 사용되어야 합니다. 이동도중사용불가능 스킬이라면 캐릭터가 즉시 멈춘다음 스킬이 사용되어야 합니다.  
플레이어가 최대한 편하게 할 수 있는 게임을 만들려고 합니다.  

추가로 타격감이 있는 게임을 만드려고 합니다.  
화면 흔들림, 타격 사운드가 적절히 조합되어야 할 것입니다.  

- 간소화된 작업 범위
캐릭터 직업을 많이 만들지는 않을 것입니다. 캐릭터 직업은 2개 정도만 하면 될듯합니다(마법사, 전사).  
접속, 스테이지 이동, 레벨업, 캐릭터의 스탯, 스킬 사용, 몬스터 사냥, 아이템 드랍, 아이템 획득, 경험치 획득, 장비 착용, 장비의 스탯, 인스턴스 던전 생성, 다른 캐릭터와의 동기화 정도를 간단한 수준으로 개발할 예정입니다.

# 폴더 의존 방향 (왼쪽요소가 오른쪽요소를 참조함)

Game (클라 로직 통합: UI + Managers + 게임로직 한 어셈블리)
 ├─ Network ─ Generated
 ├─ Packet  ─ Network
 ├─ NavMesh ─ DotRecast
 ├─ GameData
 └─ Generated

Editor (Editor 전용)
 └─ NavMesh ─ DotRecast

Network: 소켓·스레드·바이트 송수신만. Unity 의존성 최소화 (가능하면 순수 C#).
Packet: Packet ID ↔ 핸들러 매핑(PacketDispatcher), 직렬화/역직렬화 헬퍼. Network 위에 얹힘.
GameData: 게임데이터만 담당
Game: 게임 로직 + UI + 전역 매니저(Input/UI/Resource/Scene)를 **모두 포함하는 단일 클라 어셈블리**.
  - asmdef = `Scripts/Game.asmdef` (Scripts/ 루트에 위치 → UI/Managers/Game 폴더를 함께 컴파일. Network/Packet/Generated/GameData/NavMesh 는 각자 asmdef로 분리 유지).
  - **통합 배경(2026-06-30)**: 과거 UI/Managers 를 별도 어셈블리로 분리했으나, 게임상태(LocalPlayer 등)를 읽는 UI가 대부분이라 분리가 어댑터/이벤트 우회만 강제하고 실익이 작아 통합함. 이제 UI가 게임상태를 직접 참조 가능(경계 우회 불필요).
  - **네임스페이스는 계층 그대로 유지**: `Client.UI` / `Client.Managers` / `Client.Game` (어셈블리는 하나, 폴더/네임스페이스로 계층 표현). 새 UI도 "게임상태 읽는 오케스트레이터 = Game폴더, 순수 표현 위젯 = UI폴더" 관습은 유지 권장.

# 에셋 관리 규칙 (ThirdParty 아트, 내 프리팹)

## 핵심 규칙
- **서드파티 아트/VFX 원본(스프라이트, 메시, 이펙트 등)** → `Resources/` 밖에 두고 **GUID 직접 참조**로 사용.
- **경로 문자열로 동적 로드할 내 콘텐츠/UI 프리팹** → `Resources/`(현재 방식) 또는 추후 Addressables.

## 이유 (Resources 폴더의 특성)
- `Resources/` 안의 파일은 참조 여부와 무관하게 **전부 빌드에 강제 포함**되고 stripping 대상에서 제외됨. 양이 많아질수록 빌드 용량·시작 로딩·메모리에 누적 영향.
- `Resources/` 밖의 에셋은 **무언가(빌드되는 씬, 또는 그 씬이 참조하는 프리팹/SO)가 참조할 때만** 빌드에 포함됨. → 안 쓰는 에셋은 자동 제외.
- 따라서 서드파티 팩(대부분 안 씀)을 통째로 `Resources/`에 두면 안 됨. 밖에 두면 **실제 참조된 에셋만** 빌드에 들어감.

## 런타임 로드 방식별 Resources 필요 여부
- **GUID 직접 참조** (`[SerializeField]` 필드에 연결, 또는 다른 프리팹이 물고 있음) → Resources **불필요**. (서드파티 아트는 이 방식)
- **Addressables** (주소/라벨로 비동기 로드) → Resources **불필요**. (`나중에 할거` 참조)
- **`Resources.Load("경로")`** (ResourceManager 방식) → 해당 에셋이 `Resources/` 아래 있어야 함.

## 패턴: 서드파티는 "감싸서" 쓴다
- 서드파티 프리팹/스프라이트를 `Resources.Load`로 직접 부르지 않음. **내가 만든 프리팹**이 그것들을 GUID로 참조하고, 그 내 프리팹만 `Resources/`(또는 Addressables)에 둠.
- 예: `Resources/UI/Scene/UI_Login.prefab` 은 ResourceManager가 경로로 로드하지만, 그 안에서 쓰는 Layer Lab 스프라이트는 GUID 참조이므로 `Resources/`에 있을 필요 없음.
- 서드파티 프리팹을 쓰려고 `Resources/`로 **복사하지 말 것** (에셋이 두 벌 되어 수정 분기·유지보수 문제). 필요하면 이동하거나, 직접 참조/감싸기로 해결.

## 권장 배치
- 서드파티 아트/VFX 팩 → `Assets/ThirdParty/` (출처별 구분). 데모 씬/Preview/예제 폴더는 삭제.
- 내 UI/콘텐츠 프리팹 → `Resources/`(경로 로드) 유지.

## 예외: 경로로 로드되는 서드파티 팩 (curate 방식)
- 일부 서드파티 에셋은 `Skill.csv` 등 데이터 파일에 **경로 문자열**로 적혀 있고 `Resources.Load(경로)` 로 로드됨 (예: 스킬 VFX — [SkillSystem.cs](Assets/Scripts/Game/SkillSystem.cs) 의 `Resource.Load<GameObject>(skill.ProjectilePrefabPath)` 등). 이런 건 해당 프리팹이 반드시 `Resources/` 아래 그 경로에 있어야 함.
- 이때 **팩 전체를 Resources에 둘 필요는 없음.** 핵심 원리:
  - `Resources.Load` 는 **경로**로 프리팹을 찾음 → 그 **프리팹 파일만** Resources 경로에 있으면 됨.
  - 프리팹이 물고 있는 머티리얼·텍스처 등 **의존성은 GUID 참조 → ThirdParty에 있어도** 빌드에 자동 포함됨.
  - 안 쓰는 나머지는 ThirdParty에 두면 빌드시 stripping.
- **curate 방법**: 팩 전체를 `ThirdParty/` 로 옮긴 뒤, 데이터가 참조하는 **사용 프리팹만** 원래 `Resources/` 경로(데이터의 경로 문자열과 일치)로 되돌림. 의존성은 ThirdParty에 그대로 둬도 됨.
- 예: 스킬 아이콘 — Skill 데이터에 `Icon` 컬럼(4행 target=`client`, 클라 전용)을 두고 `Art/SkillIcons/skill_NNN` 경로를 적는다. 쓰는 아이콘만 `ThirdParty/500FreeSkillIcons` → `Resources/Art/SkillIcons/` 로 curate(`AssetDatabase.CopyAsset` 으로 복사하면 Sprite 임포트 설정이 보존됨). UI_PlayerHud 가 `Resource.Load<Sprite>(skill.Icon)` 로 로드. 아이콘은 서버가 안 쓰므로 컬럼을 `client` 로 두면 서버 데이터/코드는 무변경.
- ⚠️ 빌드 절약량 = "어디서도 참조 안 되는 부분"만큼. 사용 프리팹의 의존성(공유 머티리얼/텍스처)은 ThirdParty에 있어도 빌드에 포함됨.



# 참고: 오브젝트 ID값과 게임데이터 Key값의 차이
- 게임내에서 오브젝트는 ID(int64 타입)로 구분됩니다. 게임 런타임에 생성됩니다. 게임전체에서 유일한 값입니다.
- 게임데이터는 Key(int32 타입)로 구분됩니다. 1개의 엑셀파일(예: Stage)에는 여러개의 Stage 데이터가 들어있습니다. 엑셀파일에 데이터마다 Key값이 미리 입력되어 있습니다. Key값은 1개 엑셀파일 내에서만 유일한 값이고, 다른 엑셀파일(예: Monster)에는 해당 파일만의 유일한 Key값이 또 있습니다. 그래서 서버에서 Stage 게임데이터를 얻으려면 GameDataTable_Stage::Find(key) 함수로 얻어야 합니다.

# 물리 레이어 규약

물리 상호작용(클릭 이동 지면 판정, 투사체 지형/몬스터 판정)을 **역할별 레이어**로 나눠 관리한다. 레이캐스트 마스크로 판정 대상을 좁히고, 필요 시 Physics 충돌 매트릭스로 상호작용 쌍을 제어한다.

## 레이어 정의 (`ProjectSettings/TagManager.asset`)
| Idx | 레이어 | 역할 |
|---|---|---|
| 0 | Default | 미분류 fallback |
| 4 | Water | (내장) 수면 |
| 5 | UI | (내장) |
| 6 | Ground | 걸을 수 있는 지형 표면(Unity Terrain). 둔덕(벽)도 같은 콜라이더라 여기 포함 |
| 7 | Obstacle | 지형과 별개인 정적 차단물(바위/돌담/기둥/절벽) |
| 8 | Monster | 몬스터 액터 (투사체 hit 판정 대상) |
| 9 | Player | 플레이어 캐릭터 |
| 10 | Projectile | 스킬 투사체 |

## 중앙 상수 (`Scripts/Game/GameLayers.cs`)
코드는 레이어를 문자열이 아니라 `GameLayers` 상수/마스크로 참조한다. 인덱스는 TagManager 와 일치해야 한다.
- `ProjectileBlockerMask = Ground | Obstacle` — 투사체(및 추후 시야)를 막는 정적 지오메트리.
- `GroundClickMask = Ground | Obstacle | Water` — 클릭 이동 목적지를 잡는 표면.

## 레이어 부여 위치 (런타임)
씬/프리팹은 레이어가 Default 로 오므로, **런타임에 코드로 일괄 지정**한다(모든 맵 자동, 맵 재생성에도 안전).
- **맵**: `StageManager.loadStageMap` 이 맵 인스턴스화 직후 `assignMapPhysicsLayers` 호출 → Unity `Terrain` 컴포넌트를 가진 오브젝트는 Ground, 그 외 비트리거(solid) 콜라이더는 Obstacle. 트리거(수면/이벤트영역 등)·지형 콜라이더는 제외.
  - ⚠️ 콜라이더가 있는 장식은 자동으로 Obstacle 가 되어 투사체를 막는다. 막으면 안 되는 장식은 콜라이더를 빼야 한다.
- **몬스터**: `MonsterFactory` 가 콜라이더를 Monster 레이어로.
- **투사체**: `SkillSystem.spawnOneProjectile` 이 Projectile 레이어로.

## 투사체 지형 충돌 (`Projectile.cs`)
투사체는 이동 전 이전→현 세그먼트를 `Physics.Raycast(ProjectileBlockerMask, QueryTriggerInteraction.Ignore)` 로 검사해, 벽(지형 둔덕/장애물)을 물면 그 자리에서 소멸한다(벽 통과 방지). 몬스터 hit 은 별도로 기존 `OnTriggerEnter` 경로가 담당한다(레이어 분리로 서로 간섭 없음). 충돌 위치는 `SkillHitItem.exploded_on_terrain` 으로 서버에 보고 → 서버가 그 위치에 OnHit 폭발(AreaEffect)을 발동한다(폭발 중심=벽 위치라 벽 너머 딜 없음).

## 참고
- `MouseInputHandler`(클릭 이동)는 `RaycastAll`+컴포넌트 필터 방식이라 레이어 도입 후에도 무변경(회귀 없음). 추후 `GroundClickMask` 로 좁힐 여지는 있음.
- 플레이어 캐릭터는 콜라이더가 없다(서버 위치권위 이동이라 물리 불필요). Player 레이어는 향후용 예약.

## 스킬 사용
스킬의 쿨타임은 클라이언트가 먼저 체크합니다.  

스킬을 사용하면 즉시 스킬이 발동됩니다. 발사체가 있는 스킬이라면 발사체를 생성합니다.  
그런다음 서버에 스킬 사용 패킷을 보냅니다.  
서버에서는 스킬의 쿨타임과 사용가능여부 등을 판단해서 사용이 불가하면 클라이언트에게 스킬사용불가 패킷을 보내고 해당 스킬을 처리하지 않습니다. 스킬 사용이 인정되면 발사체가 있는 스킬은 서버에서도 발사체를 생성합니다.  

클라이언트는 모든 스킬을 타겟 락온 방식(오토타겟팅)으로 사용합니다.  
범위 내의 몬스터를 자동으로 감지하여 해당 몬스터를 대상으로 스킬을 사용합니다.  
만약 주변에 아무런 몬스터가 없다면 캐릭터가 바라보는 방향의 적절한 좌표를 목적지로 스킬을 사용합니다.  

클라이언트가 발사체 또는 범위공격 등이 몬스터에게 hit 했는지를 먼저 검사합니다.  
hit 했을 경우 클라이언트는 어떤 몬스터를 어떤 스킬/발사체로 hit 했는지 서버에 전송합니다.  
클라이언트는 일단은 hit 한 것으로 생각하고, 추가 이펙트 생성, 발사체 제거 등의 작업을 수행합니다.  
서버에서는 캐릭터 위치, 발사체 위치, 몬스터 위치 등을 검사하여 몬스터가 hit 가능한지 판단합니다. hit 가능하지 않다면 해당 hit을 처리하지 않습니다. hit 가능하다면 데미지를 계산하여 몬스터에게 적용하고, 클라이언트에게 데미지를 전송합니다. 그러면 클라이언트가 데미지를 화면에 표시합니다.  


# 인게임 HUD
인게임 화면에 항상 떠 있는 UI(HP/MP 바, 스킬 슬롯, 버프 바)는 **UIManager.ShowSceneUI** 로 띄우는 UI_Scene 들이다. GameScene.Init 에서 생성된다.

## UI 파이프라인 패턴 (오케스트레이터 + 표현 위젯)
게임 상태를 읽어야 하는 HUD는 두 조각으로 나뉜다.
- **오케스트레이터** (Game 폴더): LocalPlayer/SkillSystem/GameData 등 게임 상태를 매 프레임 읽어 표시할 값을 계산한다.
- **표현 위젯** (UI 폴더): 게임 상태를 모른다. 부모가 넘겨준 값(SetData)만 받아 그린다.

어셈블리는 하나로 통합됐지만(폴더 의존 방향 참조), 이 분리는 폴더 관습으로 유지한다 — "게임 상태를 읽는 화면 = Game, 순수 표시 위젯 = UI". 덕분에 위젯은 게임 로직 변경에 영향받지 않고 재사용된다.

| HUD | 오케스트레이터(Game) | 표현 위젯(UI) | 프리팹 |
|---|---|---|---|
| 플레이어 HP/MP + 스킬 | UI_PlayerHud | UI_SkillSlot | Resources/UI/Scene/UI_PlayerHud, SubItem/UI_SkillSlot |

- **표시 대상**: 내 캐릭터(방향 화살표), 몬스터(빨강 / 엘리트·보스 주황), 타 플레이어(하늘색). 아이콘은 절차 생성 스프라이트(원/화살표) + 풀링.

- **StageManager 접근자**(미니맵용 추가): `Characters`(원격+로컬 캐릭터 딕셔너리), `WorldMinX/MaxX/MinZ/MaxZ`, `CurrentMapName`.
- **배경 텍스처**: `Resources/UI/Minimap/{맵이름}_map.png` (예: `SyntyForest_map`). 런타임에 맵 이름으로 로드, 없으면 원형 배경만 표시. → 아래 **베이커 툴**로 굽는다.

# 환경설정(옵션) & 사운드

## 매니저 (Managers/Core)
- **SettingsManager** (`Managers.Settings`): 해상도(HD/FHD/QHD/4K), 창모드(전체화면/테두리없는창/창모드=`FullScreenMode`), 프레임제한(30~240/무제한), VSync. 각 항목 변경 시 `Screen.SetResolution` / `Application.targetFrameRate` / `QualitySettings.vSyncCount` 에 **즉시 적용 + 저장**. - **조작감 주의**: 이 게임은 저지연(즉시 반응)이 목표라 VSync 는 지연을 늘리는 방향이므로 **기본값 꺼짐 + 프레임 상한**으로 둔다. VSync 는 화면 찢김이 거슬리는 유저를 위한 선택지.

# 애니메이션
캐릭터/몬스터 애니메이션 시스템.

## 구조
- **컨트롤러**: `Resources/Art/Models/LayerLabCharacter.controller` 하나를 공유. 파라미터는 `Speed`(이동 블렌드), `CastSpeed`(시전/공격 배속) 둘. **레이어 2개**: `Base`(전신) + `LowerBody`(하체 마스크 오버라이드 — 스킬 발동 중 이동 시 다리만 걷기/뛰기. 아래 "상/하체 분리" 참조).
- **재생 메커니즘 4종**: ① 연속(`Speed` 블렌드 Idle/Walk/Run) ② 원샷(**상태 이름으로 직접 CrossFade** — Jump·GetHit·Dance/Emoji·Melee·Fire) ③ 캐스팅 홀드(`Cast_*` 마지막 프레임 정지 → 발동 시 `Fire_*`) ④ 사망(`Dead`). 원샷은 파라미터 없이 by-name 재생이라 클립이 늘어도 컨트롤러 편집 불필요.
- **공용 구동(driver)**: 플레이어(로컬+원격)·몬스터 모두 `IActorAnimator`(=`AnimatorActorAnimator`) 하나로 구동한다. 게임로직(`PlayerCharacter`/`MonsterObject`)은 "어떤 상태인가"라는 의미만 넘기고(이동/사망/시전/피격…), 실제 Animator 변환·블렌딩·원샷 추적은 드라이버가 전담. 몬스터는 종족별 **AnimatorOverrideController**(Slime/Goblin: 구조 공유, 클립만 교체)로 자기 클립을 쓴다. 공유 유틸 `AnimStates`(상수) + `AnimPlay`(상태·파라미터 유무로 안전 재생 — 없는 것엔 no-op).
	- 플레이어는 `PlayerCharacter.Awake` 가 드라이버를 `AddComponent` 후 위임(예측/화해로 결정한 이동 플래그만 매 프레임 `SetMoving` 전달) / 몬스터는 `MonsterFactory` 가 런타임 `AddComponent`. 결정은 각 액터, 재생은 드라이버 — 로직이 Unity Animator 에 묶이지 않는다.
- **리타게팅**: 캐릭터·클립 모두 Humanoid → 컨트롤러 1개로 전 직업/프리셋 공유. 외부 클립도 Humanoid 재임포트하면 사용 가능(예: KayKit).
- **위치는 코드 구동**: 전 클립 Apply Root Motion OFF. 애니는 시각만, 위치는 Mover(이동동기화)가 담당 → "점프하며 이동"이 자연스럽게 됨.

## 상/하체 분리 (스킬 발동 중 이동) — 2026-07-05
스킬 발동(Fire) 애니가 재생되는 도중에 캐릭터가 이동하면 **하체는 걷기/뛰기, 상체는 발동 모션**을 동시에 낸다.
- **컨트롤러**: `Base` 레이어(전신, 로코모션·시전·발동·원샷 전부)는 그대로. **`LowerBody` 레이어** 추가 = 하체 아바타 마스크(`LowerBodyMask`, LeftLeg+RightLeg) Override. 상태 1개(`LowerLocomotion`)가 base 의 Locomotion 블렌드트리를 **공유**(같은 `Speed` 파라미터).
- **드라이버(`AnimatorActorAnimator`)가 weight 관리**: 스킬 시전/발동 중이면(`m_lowerBodyOverride`) LowerBody weight=1, 아니면 0. idle↔run 은 `Speed` 가 담당하므로 weight 를 이동여부로 껐다 켜지 않는다.
  - 잠금 중(정지, Speed 0): 하체=Idle, 상체=시전/발동. (마법 시전은 다리 고정이라 전신과 사실상 동일)
  - 잠금 끝 + 이동(Speed 1): 하체=Walk/Run, 상체=발동 유지.
  - ※ "발동 중이면 항상 1"로 두는 이유: 발동애니가 잠금보다 긴 스킬(얼음지대)에서 이동 시작 시 weight 페이드인이 다리를 뒤처지게 해 튀어나가 보였음. weight 를 미리 1로 두면 이동 시작 시 `Speed` 스냅만 작동해 다리가 곧바로 달림.
- **전제 불변식**: `CastDelayMs ≤ ActionLockMs` (시전애니는 항상 잠금 안이라 시전 중엔 이동 불가 → 분리는 발동애니에만 필요). 스킬 데이터에서 유지.
- 몬스터는 `PlayCast/PlayFire` 를 안 써서 LowerBody weight 가 항상 0 → **영향 없음**.
- 한계/튜닝: 허리 이음새(마스크 범위), 페이드 시간(`k_lowerBlendTime`). 특정 발동 클립에 중요한 하체 동작이 있으면 잠금 중 Idle 로 보일 수 있음(마법은 무해).

## 상태 → 클립 매핑 (혼합 팩, 모두 Humanoid)
상태명은 의미 기반이고, 스킬/직업 데이터가 재생할 상태명을 지정한다.
| 상태 | 클립(팩) |
|---|---|
| Locomotion(`Speed`) | LayerLab Idle/Walk/Run |
| `Jump` | LayerLab Action_Jump |
| `GetHit` / `Stun` | Blink GetHit / StunnedLoop |
| `Dead` | LayerLab Reaction_Knockout |
| `Melee_1` / `Melee_2` | Blink MeleeAttack_OneHanded / TwoHanded |
| `Cast_Magic`(홀드·loop) → `Fire_Magic_1/2/3` | KayKit Ranged_Magic_Spellcasting → Shoot / Raise / (Direct2H) |
| `Cast_Melee`(홀드) → `Fire_Melee` | Human MagicAttackDirect1H Load → base |

- **임포트 규칙**: Loop ON = Idle/Walk/Run·Stun·Dance·캐스팅 채널. Loop OFF = 그 외 원샷. Root Motion 은 전부 OFF.
- **몬스터 오버라이드**: `Slime_Override`(idle/walk→슬라임, Dead→슬라임 Dead, `Melee_1`→슬라임 Attack, `GetHit`→Rig_Damage) / `Goblin_Override`(패스스루 = 캐릭터 Humanoid 클립 재사용).

## 전투/액션 연결
- **스킬 시전**: 스킬데이터 `CastAnim`/`FireAnim` 상태명을 `PlayCast`(홀드) → (CastDelay 후) `PlayFire`(발동)로 재생. `CastSpeed = min(1, 0.8/시전초)` — "짧은 시전은 원래속도(부분재생)·긴 시전만 느리게". 원격은 `AbilityCastNtf`(윈드업)+`SkillCastNtf`(발동)로 재현.
  - **상태별 배속**: 발동 상태의 실제 재생속도 = `state.speed × CastSpeed`. 특정 발동 클립만 빠르게/느리게 하려면 컨트롤러에서 그 상태의 `speed` 를 조정한다(예: `Fire_Magic_2`=IceField 전용, speed 2 로 발동애니 2배).
- **이동 시작 애니**: 정지→이동 순간 `Speed` 를 **즉시 1(Run)로 스냅**(Walk 램프 없이). 위치는 첫 프레임부터 풀스피드(`LocalPlayerMover`)라 애니만 램프하면 다리가 뒤처져 "앞으로 튀어나가" 보이기 때문. 정지(→0)는 damp 로 부드럽게 감쇠. (현재 이동은 이진이라 `SetSpeed` 중간값은 미사용 = Walk 는 사실상 미사용.)
- **점프/감정표현**: 연출 전용 패킷 `ActorActionReq/Ntf` 로 서버가 AOI relay → 원격도 재생. 감정표현은 `UI_EmotePanel`(HUD 이모지 버튼)에서 `LocalEmote(상태명)` 호출.
- **피격/사망/부활**: `SkillDamageNtf`→`PlayHit`(Locomotion·감정표현 중만, 0.4초 쓰로틀), `ObjectDeathNtf`→사망 + 입력차단(`IsDead` 게이트), `ObjectReviveNtf`→자동 리스폰(사망 N초 후 서버가 부활).
- **원샷 이동취소**: 감정표현 재생 중 이동/점프/스킬/피격이 오면 즉시 끊고 전환한다(댄스=loop, 이모지=1회 재생).

- 프로필 오버라이드: **ColorAdjustments**(채도 +15, 대비 +10 — "화려함"의 핵심), **Bloom**(intensity 2), **Vignette**(0.46), **LiftGammaGain**(색보정). 색이 과하면 이 프로필의 Saturation/Contrast/Bloom 값을 낮춘다(Global Volume 선택 → 프로필 편집).

## 조명 (웜/쿨 2등 라이트)
- **Key** (`Directional Light`): 웜 골든 `(1.0, 0.90, 0.78)`, 강도 1.6. (Demo 원본은 `(1.0, 0.76, 0.50)`이지만 너무 주황이라 **몬스터/캐릭터가 누렇게** 떠서 완화한 값이다.)
- **Fill Light**: 쿨 블루 `(0.60, 0.69, 0.90)`, 강도 0.5, 그림자 없음 — 그림자 쪽 보조광(웜/쿨 대비로 색을 풍부하게).
- **Fog**: ON(따뜻한 크림색, Linear 20~600). 게임 카메라 거리에선 아주 은은.
- 앰비언트는 Skybox 모드(기본 스카이박스, 두 씬 동일).

## 주의
- **미니맵 텍스처 베이크는 이 포스트프로세싱/조명과 무관**하다(베이커가 안개·씬조명을 격리해 렌더). 조명을 바꿔도 미니맵 배경은 영향받지 않는다.
- **키라이트의 웜 정도가 캐릭터/몬스터 색감을 좌우한다** — 누런기가 거슬리면 Key 색을 더 중성(흰색 쪽)으로, 밋밋하면 더 웜하게 조절.

# 나중에 할거
1. ResourceManager에 Addressables 도입하기
2. 리소스 로드 비동기 호출에 Task 대신 UniTask 사용하기
3. PoolManager + Poolable — 발사체/이펙트 풀링. 곧 필요해질 가능성. ResourceManager 와 통합
