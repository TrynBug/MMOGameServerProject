- Unity 프로젝트 제어 방법
  - 이 프로젝트의 `Assets/Editor/AIEditorBridge.cs`에는 에디터 제어 브릿지가 구현되어 있습니다.
  - 유니티 에디터에게 명령을 내리고 싶을 때는 `Assets/Editor/ai_command.txt` 파일을 생성하고 아래 명령어 중 하나를 작성하세요. 명령은 한 줄로 작성하며, 인자는 콜론(`:`)으로 구분합니다. 좌표는 콤마(`,`)로 구분합니다.
  - 명령 실행 결과는 `Assets/Editor/ai_command_result.txt` 파일에 작성됩니다. 첫 줄에 `OK` 또는 `ERROR`가 오고, 그 다음 줄부터 상세 내용이 옵니다. 다음 명령을 보내면 결과 파일은 덮어써집니다.
  
  - **기본 제어**
    - `PLAY`: 게임 플레이 모드 시작
    - `STOP`: 게임 플레이 모드 종료
    - `REFRESH`: 에셋 데이터베이스 리프레시 (컴파일 유도)
  
  - **컴파일 / 테스트**
    - `COMPILE_CHECK`: 스크립트를 강제 재컴파일하고 에러/경고를 결과 파일에 출력합니다. 컴파일이 비동기이므로 명령 후 잠시 대기한 뒤 결과 파일을 확인해야 합니다. `PROJECT_INFO`로 컴파일 진행 여부를 폴링할 수 있습니다.
    - `RUN_EDIT_MODE_TESTS`: 모든 EditMode 테스트를 실행하고 결과를 출력합니다.
    - `RUN_EDIT_MODE_TEST:<TestFullName>`: 특정 EditMode 테스트만 실행합니다.
  
  - **씬 조작**
    - `SCENE_DUMP`: 현재 활성 씬의 게임오브젝트 계층, 위치, 컴포넌트 목록을 출력합니다.
    - `SCENE_DUMP:<scenePath>`: 지정 씬 파일의 내용을 출력합니다. 현재 작업 중인 씬에는 영향 없습니다. (예: `SCENE_DUMP:Assets/Scenes/Main.unity`)
    - `CREATE_SCENE:<scenePath>`: 빈 씬을 생성하고 저장합니다.
    - `OPEN_SCENE:<scenePath>`: 씬을 단일 모드로 엽니다.
    - `SAVE_SCENE`: 현재 씬을 저장합니다.
  
  - **게임오브젝트 조작**
    - `CREATE_PRIMITIVE:<Type>:<name>:<x,y,z>`: 프리미티브를 생성합니다. Type은 `Cube`, `Sphere`, `Capsule`, `Cylinder`, `Plane`, `Quad` 중 하나. 좌표가 없으면 원점에 생성됩니다. (예: `CREATE_PRIMITIVE:Cube:Player:0,1,0`)
    - `CREATE_EMPTY:<name>:<x,y,z>`: 빈 게임오브젝트를 생성합니다.
    - `ADD_COMPONENT:<objectPath>:<componentTypeName>`: 게임오브젝트에 컴포넌트를 추가합니다. objectPath는 `Parent/Child/GrandChild` 형식의 씬 계층 경로입니다. 컴포넌트는 FullName(`UnityEngine.Rigidbody`) 또는 단순명(`Rigidbody`)으로 지정할 수 있습니다. 단순명 사용 시 동명 타입이 여러 어셈블리에 있으면 모호할 수 있으므로 FullName을 권장합니다.
    - `DELETE_OBJECT:<objectPath>`: 게임오브젝트를 삭제합니다.
    - `SET_POSITION:<objectPath>:<x,y,z>`: 위치를 변경합니다.
  
  - **프리팹**
    - `CREATE_PREFAB:<objectPath>:<prefabPath>`: 씬의 게임오브젝트를 프리팹으로 저장합니다. (예: `CREATE_PREFAB:Player:Assets/Prefabs/Player.prefab`)
    - `INSTANTIATE_PREFAB:<prefabPath>:<name>:<x,y,z>`: 프리팹 에셋을 씬에 인스턴스화합니다.
  
  - **콘솔 / 정보**
    - `GET_CONSOLE_LOGS`: 콘솔의 모든 로그(INFO/WARN/ERROR)를 출력합니다.
    - `CLEAR_CONSOLE`: 콘솔을 클리어합니다.
    - `PROJECT_INFO`: Unity 버전, 프로젝트 경로, 활성 씬, 플레이 모드 여부, 컴파일 중 여부를 출력합니다.
  
  - 코드를 새로 생성하거나 수정했다면, 유니티가 즉시 컴파일할 수 있도록 반드시 `REFRESH` 또는 `COMPILE_CHECK` 명령을 보내야 합니다. 컴파일 결과까지 확인하려면 `COMPILE_CHECK`를 사용하세요.

게임서버는 Sector가 구현되어 있어서 캐릭터가 이동함에따라 Sector를 이동하고, 클라이언트에게 오브젝트 스폰/디스폰 패킷을 보냅니다. 길찾기는 NavMesh를 사용합니다.

서버에 접속하여 로그인을 하고 첫 Stage에 입장하는 것 까지 만들어져 있습니다.

# 최종 목표
- 최종 목표
실제 출시할 제품을 만드는 것은 아닙니다.  
게임 개발을 경험해보고, 제품으로 이어질 수 있는지의 가능성을 체크하는것이 목표입니다.  
트리 오브 세이비어와의 차이점은, 현재 게임은 가벼운 hack and slash 장르로 만들 것입니다. 수많은 몬스터, 수많은 투사체, 수많은 스킬 이펙트를 어느정도까지 렉 없이 처리할 수 있는지 가능성을 보려고 합니다.  

그리고 조작감이 아주 가벼운 게임을 만드려고 합니다.  
플레이어가 캐릭터를 움직였을 때 즉시 반응해야 하며, 멈추고 싶을때 즉시 멈추어야 합니다. 스킬들의 선딜레이, 후딜레이도 거의 없어야 합니다(쿨타임은 있음). 텔레포트 등의 회피 스킬도 사용가능한경우 즉시 발동되어야 합니다.  
캐릭터가 이동하는 도중에 스킬을 사용하면, 이동도중사용가능 스킬이라면 스킬이 즉시 사용되어야 합니다. 이동도중사용불가능 스킬이라면 캐릭터가 즉시 멈춘다음 스킬이 사용되어야 합니다.  
플레이어가 최대한 편하게 할 수 있는 게임을 만들려고 합니다.  

추가로 타격감이 있는 게임을 만드려고 합니다.  
화면 흔들림, 타격 사운드가 적절히 조합되어야 할 것입니다.  

- 간소화된 작업 범위
캐릭터 직업을 많이 만들지는 않을 것입니다. 캐릭터 직업은 2개 정도만 하면 될듯합니다(마법사, 전사).  
접속, 스테이지 이동, 레벨업, 캐릭터의 스탯, 스킬 사용, 몬스터 사냥, 아이템 드랍, 아이템 획득, 경험치 획득, 장비 착용, 장비의 스탯, 인스턴스 던전 생성, 다른 캐릭터와의 동기화 정도를 간단한 수준으로 개발할 예정입니다.

# 폴더 의존 방향 (왼쪽요소가 오른쪽요소를 참조함)

Game
 ├─ Network ─ Generated
 ├─ Packet  ─ Network
 ├─ NavMesh ─ DotRecast
 ├─ GameData
 ├─ Managers ─ UI
 └─ UI

Editor (Editor 전용)
 └─ NavMesh ─ DotRecast

Network: 소켓·스레드·바이트 송수신만. Unity 의존성 최소화 (가능하면 순수 C#).
Packet: Packet ID ↔ 핸들러 매핑(PacketDispatcher), 직렬화/역직렬화 헬퍼. Network 위에 얹힘.
Game: 게임 로직. 패킷 핸들러를 등록해서 자기 상태를 갱신.
Managers: 전역 매니저 모음 (Input/UI/Resource/Scene). 다른 게임 시스템(Network, Game) 은 모름. UI 는 참조함 (UIManager 가 UI 베이스 타입을 다뤄야 하므로).
UI: UI 베이스 클래스(UI_Base, UI_Popup, UI_Scene)와 실제 UI 클래스들. Game 도 Managers 도 모름 (가장 하위).
GameData: 게임데이터만 담당

# 조작
## 캐릭터 조작
마우스 좌클릭으로 캐릭터를 이동시킵니다.  
마우스 왼쪽버튼을 누르고 있는 동안만 캐릭터가 마우스 위치로 이동합니다. 왼쪽버튼을 떼면 캐릭터가 즉시 멈춥니다.  

클라이언트는 마우스 왼쪽버튼으로 땅을 찍으면 즉시 경로를 계산하여 이동을 시작합니다.   
그런다음 서버에 목적지를 전송합니다.  
서버에서는 목적지가 도달가능한지 확인하고, 동일한 경로계산으로 캐릭터를 움직입니다. 목적지가 잘못되었다면 클라이언트에게 위치 보정 패킷을 보내야 합니다.   
왼쪽버튼을 누르고 있는 동안에는 화면이 캐릭터를 따라가기 때문에 마우스가 위치한 좌표가 계속해서 변경될 것입니다. 그래서 왼쪽버튼을 누르고 있는 동안에는 서버에 주기적으로(대략 500ms) 목적지를 전송해야 합니다.  
왼쪽버튼을 떼면 캐릭터가 즉시 멈추고, 서버에 현재 캐릭터의 위치를 전송합니다.  
서버는 현재 캐릭터의 위치가 서버위치의 오차범위 내에 있다면 클라이언트의 위치를 인정합니다. 위치가 잘못되었다면 클라이언트에게 위치 보정 패킷을 보내야 합니다.  

## 스킬 사용
스킬의 쿨타임은 클라이언트가 먼저 체크합니다.  

스킬을 사용하면 즉시 스킬이 발동됩니다. 발사체가 있는 스킬이라면 발사체를 생성합니다.  
그런다음 서버에 스킬 사용 패킷을 보냅니다.  
서버에서는 스킬의 쿨타임과 사용가능여부 등을 판단해서 사용이 불가하면 클라이언트에게 스킬사용불가 패킷을 보내고 해당 스킬을 처리하지 않습니다. 스킬 사용이 인정되면 발사체가 있는 스킬은 서버에서도 발사체를 생성합니다.  

클라이언트는 모든 스킬을 타겟 락온 방식(오토타겟팅)으로 사용합니다.  
범위 내의 몬스터를 자동으로 감지하여 해당 몬스터를 대상으로 스킬을 사용합니다.  
만약 주변에 아무런 몬스터가 없다면 캐릭터가 바라보는 방향의 적절한 좌표를 목적지로 스킬을 사용합니다.  

클라이언트가 발사체 또는 범위공격 등이 몬스터에게 hit 했는지를 먼저 검사합니다.  
hit 했을 경우 클라이언트는 어떤 몬스터를 어떤 스킬/발사체로 hit 했는지 서버에 전송합니다.  
클라이언트는 일단은 hit 한 것으로 생각하고, 추가 이펙트 생성, 발사체 제거 등의 작업을 수행합니다.  
서버에서는 캐릭터 위치, 발사체 위치, 몬스터 위치 등을 검사하여 몬스터가 hit 가능한지 판단합니다. hit 가능하지 않다면 해당 hit을 처리하지 않습니다. hit 가능하다면 데미지를 계산하여 몬스터에게 적용하고, 클라이언트에게 데미지를 전송합니다. 그러면 클라이언트가 데미지를 화면에 표시합니다.  


# 핵 검사
클라이언트의 부정 이동, 부정 스킬 사용 등의 핵 검사는 개발과정에서 반드시 통합되어야 하는 로직이 아니라면, 게임이 어느정도 완성된 다음 추가할 예정입니다.  

# 그래픽
트리 오브 세이비어와 유사하면서, 테일즈위버 느낌 나는 그래픽을 만들 예정입니다.  
아직 계획수립, 가능성 조사는 하지 않았습니다.  
다만 나중에 그래픽을 붙일 수 있도록 캐릭터 모델은 Animator + Renderer 컴포넌트만 교체하면 되도록 구조를 짜야 합니다.
