
## 오늘 한 작업 요약

**1. 오브젝트 상속 구조 개편**
- `ActorObject` 도입: `StageObject` → `ActorObject` → `Character` 로 계층화
- ActorObject 는 "상호작용 가능한 액터"의 공통 베이스 (Character, Monster, 향후 Pet/NPC)

**2. 스탯 시스템 설계 + 구현**
- 모델 B (in-place 누적): 소스가 붙을 때 `ApplyStat`, 빠질 때 `RemoveStat`. 출처는 추적 안 함(소스 객체가 자기 기여분을 앎)
- 4가지 Op: 합연산(Add), 합연산%(AddPct), 곱연산(Amp), 점감곱연산(Reduce) + 총합(Total)
- 총합 공식: `Add × (1+AddPct%) × (1+Amp%) × (1−Reduce%)` → clamp
- 곱/점감곱 raw 는 ×0 미만 금지(MinApplyValue clamp)로 역연산 안전 보장

**3. 게임데이터/enum (네가 만듦)**
- `EStat`(45개), `EStatGroup`(9개: Str/Int/Hp/Mp/PDef/MDef/MoveSpd/AtkSpd/CritRate), `EStatOp`, `EJob`
- `Stat`, `JobBase`, `Monster` 테이블 (JobBase/Monster 는 `Stat#/StatValue#` 순회 형태)
- `GameDataTable_Stat` 에 역인덱스 구성: `FindDataByStat`, `GetGroupInfo`(그룹→구성스탯), `GetStatGroup`
- `GameDataTable_JobBase` 에 `FindDataByJob`

**4. 스탯 컴포넌트 (공통 베이스 + 2종)**
- `StatComponentBase`: 공식 + 합성/갱신 흐름. 저장은 순수가상으로 위임
- `CharacterStatComponent`: `double[EStat::Max]` 조밀 배열 (캐릭터용)
- `BasicStatComponent`: raw=`unordered_map`(희소) + 총합=`double[EStatGroup::Max]` (Monster/Pet 등 경량)

**5. 현재HP/MP (ActorObject)**
- `m_curHp/m_curMp` + clamp setter + `IsDead()`
- 최대치는 `GetStatTotal(EStatGroup)` 순수가상으로 통일, `GetMaxHp/GetMaxMp` 는 공통 구현

**6. Character / Monster 연동**
- Character: 생성 시 JobBase 기본스탯 적용 → 풀피
- Monster: 생성 시 종류데이터 스탯 적용 → 풀피

**검증:** Character/Basic 둘 다 동일 입력에서 `StrTotal=41.3724` 확인 (공식 + 역연산 + 두 저장방식 일치)

**현재 구조:**
```
StageObject
└─ ActorObject (현재HP/MP, GetStatTotal 가상)
   ├─ Character (CharacterStatComponent, JobBase)
   └─ Monster   (BasicStatComponent, 종류데이터)

StatComponentBase (공식+합성)
├─ CharacterStatComponent (조밀 배열)
└─ BasicStatComponent     (희소맵 + 그룹 총합배열)
```

**미완 (의도적):** 2차 파생(공격력 등) 게임로직, Monster AI/이동/스폰, 레벨/스탯포인트, character.proto 임시 스탯 멤버 정리, Pet/NPC/Prop.
