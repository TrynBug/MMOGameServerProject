# 타격감 설계 (스킬 사용감)

> 목표: "스킬 사용하는 맛"이 좋은 시스템. 참고 게임(LoL·히오스·D4) 분석 + 타격감 요소의 구체 구현 + 우리 클라/서버 구조 적용안 정리.
> 우리 전제: C++ IOCP 서버 권위 + Unity 클라 예측, 결정론적 이동(서버·클라 동일 ease-out 공식), 즉발 조작감, 물량 hack&slash.
>
> 구성: 1부 참고게임 분석 · 2부 타격감 요소 구현(+코드 스케치) · 3부 우리 시스템 적용 · **4부 에셋→시스템 연결(wiring)** · **5부 구현 로드맵(어디서부터 시작)**.

---

## 0. 한 줄 원리

**타격감 = "화면을 흔드는 global juice"가 아니라, "타격 순간에 집중된, 여러 채널이 동기화된 인과(因果) 피드백"이다. 그리고 그게 깨끗한 위계(clarity) 위에 얹힐 때만 또렷하게 전달된다.**

아래 4개 게임이 같은 법칙의 성공/실패 사례다. 우리 물량 hack&slash는 구조적으로 히오스의 함정(동시 다발 난전 + 동시 AoE)에 노출돼 있으므로, "위계와 노이즈 예산" 관리가 선택이 아니라 필수다.

# 1부. 참고 게임 분석

## 1. League of Legends — 화면 흔들림 없이도 좋은 타격감

핵심: 화면 흔들림을 *안 쓰는 게 아니라 안 쓰는 게 유리*하다. 전장을 읽어야 하는 게임에서 global 흔들림은 정보를 파괴하므로, 그 자리를 **타격 지점 local 피드백**으로 채운다.

1. **피드백 채널의 동시 발화** — 적중하는 그 순간에 ①임팩트 VFX, ②펀치 히트사운드, ③타겟 피격반응(체력바·데미지숫자·흠칫)이 한 프레임으로 겹친다. "내가 때렸다"가 강하게 인식된다.
2. **시전 이펙트와 임팩트 이펙트 분리** — travel 연출과 hit 연출이 별개 애셋. 임팩트는 짧고 강하게 "팟" 터져 시선을 모은다. → 우리 `OnHitSkillKey`(직격≠폭발) 구조가 이미 이걸 데이터로 표현.
3. **사운드가 타격감의 절반 이상** — Riot 공식: 어택 트랜지언트 강한 히트음을 적중 프레임에 정확히 깐다. 사운드를 카테고리화(힐=윈드차임 등)해 청각으로 read를 보강. "시각보다 청각이 더 정확할 때가 많다."
4. **Anticipation → 발동 → follow-through** — 빨라도 선동작이 분명해 적중이 "예고된 약속의 실현"처럼 느껴진다.
5. **Clarity 3원칙 (Riot 공식)** — ①게임플레이가 명확히 전달, ②위계 보존(데미지·CC 큰 스킬이 더 화려), ③노이즈 최소화. "전부 11로 올리면 명료성 파괴."

## 2. 히어로즈 오브 더 스톰 — 타격감·가시성이 나쁜 이론적 이유

LoL의 명료성 3기둥을 **세 개 모두 동시에, 구조적으로** 위반한다. "타격감 나쁨"과 "가시성 나쁨"은 같은 뿌리(클래리티 설계 실패)의 두 증상.

1. **Hierarchy 부재 ("전부 11로 올림")** — 두껍고 채도 높은 아트 + 과한 글로우로 기본기와 궁극기의 시각 우선순위가 거의 같다. 무엇이 위험한지 안 읽힌다.
2. **Noise 과잉 (팀 단위 상시 난전)** — 공유 경험치·팀 중심 설계라 영웅·용병이 좁은 지역에 상시 뭉치고, 동시 AoE·지속 장판이 겹쳐 화면이 포화된다.
3. **피드백 비동기·비집중 (타격감의 직접 원인)** — 이펙트가 크고 오래 깔리는 지속형 위주라 "맞는 순간"의 트랜지언트가 묻힌다. 타겟 피격반응도 약하다.
4. **청각 위계 부재** — 동시다발 사운드가 뭉개져, 시각이 포화돼도 청각이 구해주지 못한다.
5. **카메라·오클루전** — 영웅·이펙트가 서로 가려 가시성을 한 번 더 깎는다.

> 정리: LoL은 "local·동기화·위계"로 타격감을 *집중*시키고, 히오스는 "global·비동기·평탄"으로 *분산*시킨다.

## 3. Diablo 4 — hack&slash 스킬 사용감

"한 방 한 방이 묵직하게 꽂히는" 느낌을 **데미지 적용을 비주얼·물리와 정렬**해서 만든다. (Blizzard 공식 설명)

1. **Animated Payload** — 과거 디아블로는 단일 프레임·단일 영역 판정. D4는 타격 영역(payload)을 *여러 프레임에 걸쳐 애니메이션*해서 VFX와 판정을 프레임 단위로 일치시킨다. "보이는 것 = 맞는 것."
2. **방향성 래그돌 물리** — 히트 이펙트를 스킬 방향으로 흐르게 하고, 맞은 지점에 방향성 물리력을 가한다(무릎 맞으면 무릎에서 피·다리 꺾임). 타격이 *물리적 사건*으로 보인다. 물량이 내 스킬 방향대로 우수수 날아가는 게 손맛의 핵심.
3. **Skill-driven death** — 무엇으로 죽였느냐에 따라 시체 연출이 달라져 물량 처치가 안 지루하다.
4. **즉발 반응성 + Unstoppable** — 내가 쓰기로 한 행동은 끝까지 실행된다는 통제감.

> 우리 적용: 서버는 지금처럼 단일 시점 범위쿼리 1회로 판정하되, **클라 VFX가 판정 시점·모양에 정확히 싱크**되고 **타겟이 스킬 방향으로 넉백/흠칫**하면 D4 손맛의 80%를 가져온다.

## 4. D4 Rogue "Shadow Step"의 쫀득함 — root motion인가?

**결론: root motion 때문이 아니고, root motion이어서도 안 된다.**

- root motion = 애니메이션 클립이 캐릭터의 월드 이동을 구동. 그런데 Shadow Step은 *임의 위치의 적 뒤*라는 가변 목적지로 워프 → 고정 클립으로 표현 불가 → **이동 변위 자체는 코드 구동(타겟 스냅 + 보간)**이지 root motion이 아니다.
- "쫀득함"의 정체 4가지 합성:
  1. **짧은 anticipation(선동작)** — 그림자로 가라앉는 0.1초 안팎의 "당김"이 발동을 약속으로 만든다.
  2. **비선형 ease 커브** — 빠르게 출발해 도착 직전 감속. → 우리 `f=1-(1-t)^2` 그 자체.
  3. **도착 임팩트의 hitstop** — 백스탭이 꽂히는 순간 수십 ms 프레임 홀드. 쫀득함의 체감 대부분이 사실 이것.
  4. **타겟 스냅 + Unstoppable** — 항상 깔끔히 도착하고 끊기지 않는 통제감.
- **중요:** root motion은 애니(클라)가 위치를 만드는 *비결정론적* 방식이라, 우리의 "서버·클라 동일 공식 결정론 이동" 원칙과 정면충돌. 우리가 코드 구동 ease-out을 쓴 건 결과적으로 정답. Shadow Step 손맛은 root motion 없이 ①선동작 + ②기존 ease-out + ③도착 hitstop + ④타겟 스냅으로 이식 가능.

# 2부. 타격감 요소 구현

## A. Hitstop (히트스톱) — 가장 싸고 효과 큰 요소

**원리:** 충돌 순간 캐릭터를 몇 프레임 얼렸다 푼다. 충돌이 일어났음을 눈이 등록할 시간을 주고, "뚫으려면 큰 힘이 필요했다"는 인상 → 한 방이 묵직해진다. 격투게임은 ~10프레임을 쓰지만 그건 캔슬윈도우 등 게임플레이 용도가 겹쳐서고, 우리는 순수 연출용이라 **짧게**가 정답.

**권장 값 (60fps):**
- 일반 타격: **2~3프레임 (33~50ms)**
- 큰 데미지/크리/처치: **4~6프레임 (66~100ms)**
- 궁극기 착탄: **6~8프레임** (+ 선택: 약한 카메라 킥)

**절대 금지 — `Time.timeScale` 글로벌 정지:**
- (1) 서버는 모든 플레이어를 위해 권위적으로 계속 시뮬레이션 → 클라가 멈춰도 서버는 안 멈춰서 끝나면 위치 어긋남.
- (2) timeScale은 그 클라의 *모든 것*(다른 플레이어·내 이동)을 멈춰 즉발 조작감 파괴.

**대신 — per-object 정지 (순수 클라, 패킷 0): 애니만 멈춘다.**
```
타격 대상 몬스터의 "애니메이션만" N ms 멈춘다:
  Animator.speed = 0  (→ N ms 후 원복)
  위치는 건드리지 않는다 — SnapshotInterpolator 가 계속 굴린다.
서버: 아무것도 안 함. 시뮬레이션 그대로.
```

> **위치는 왜 안 멈추나 (구현에서 배운 것):** 원격 몬스터 위치는 `NetClock.RenderTimeMs` 기준 보간인데, 정지 중에도 RenderTime 은 계속 흐른다. 위치까지 홀드하면 해제 순간 "지금 있어야 할 위치"로 한 프레임에 튀어(순간이동) 보인다. 초기 구현이 위치를 홀드했다가 정확히 이 스냅을 겪었다. 해결: **애니만 멈추고 위치는 보간 유지.** 33~50ms 동안 미끄러지는 거리는 0.1유닛 수준이라 사실상 안 보이고, hitstop 의 묵직함은 애니 정지 + 스케일팝에서 대부분 나온다. (진짜 "딱 멈춤"이 필요하면 위치 홀드 + 해제 후 ~100ms catch-up 블렌딩이 대안이지만, 네트워크 보정과 엉키고 코드가 늘어 1차에는 안 한다.)

**가해자(플레이어 본인)는 얼리지 않는다.** 마우스 상시 이동 즉발 컨셉이라 플레이어를 얼리면 조작감이 끊긴다. → **피격 대상(몬스터)만 hitstop.** 플레이어 쪽 타격감은 임팩트 VFX+히트스파크+사운드로.
**물량 주의:** 대상별 독립 적용. hitstop 은 `animator.speed` 1줄이라 비용이 사실상 0 → **동시 개수 캡 불필요**(캡은 VFX·데미지텍스트·오디오 같은 비싼 채널에만 — 3부 물량 예산).

**구현 스케치 (`HitStop.cs`, 피격 몬스터에 부착 · 순수 클라):**
```csharp
public class HitStop : MonoBehaviour {
    Animator anim; float prevSpeed, timer; bool active;
    // 대상 몬스터에 부착(없으면 AddComponent). 겹치면 더 긴 쪽으로 연장.
    public static void Trigger(MonsterObject m, float ms){
        var hs = m.GetComponent<HitStop>() ?? m.gameObject.AddComponent<HitStop>();
        if(!hs.active){ hs.anim = hs.GetComponentInChildren<Animator>(); hs.active = true;
                        if(hs.anim){ hs.prevSpeed = hs.anim.speed; hs.anim.speed = 0f; } }
        hs.timer = Mathf.Max(hs.timer, ms/1000f);
    }
    void Update(){
        if(!active) return;
        timer -= Time.unscaledDeltaTime;                 // timeScale 무관(글로벌 정지 금지)
        if(timer <= 0f){ if(anim) anim.speed = prevSpeed; active = false; }
    }
    // 위치는 손대지 않는다 → 보간이 계속 굴러 순간이동 없음. 캡 없음(비용 0).
}
```

## B. 넉백 — 유일하게 서버가 관여하는 요소

**방향 모드 (3가지):**

| 모드 | 방향 | 쓰는 스킬 |
|---|---|---|
| `SkillDir` | 시전 방향으로 균일 (D4식 "휘두른 방향으로 다 날아감") | 파이어볼 직격, 블레이즈 빔 |
| `RadialFromCaster` | 캐스터 중심에서 바깥 방사 | 전격방출 |
| `RadialFromImpact` | 폭발/착탄 지점에서 바깥 방사 | 파이어볼 폭발, 메테오, 글라이드 충격파 |

D4 "방향성 래그돌" 손맛의 핵심. 적이 내 스킬 방향대로 날아가면 타격이 물리적 사건으로 읽힌다.

**파라미터:** 거리, 시간, 커브 = **ease-out (`f=1-(1-t)^2` 그대로)**. 넉백 = 새 시스템이 아니라 **강제이동(`ApplySkillMovement`)을 타겟 몬스터에 적용**하는 것.

**아키텍처 — 서버 권위 (필수):**
넉백이 몬스터 실제 위치를 바꾸면 이후 범위판정·충돌·AI에 영향 → 클라 장식만으론 불가. 다행히 우리는 이미 (1) 결정론적 강제이동 primitive, (2) 설계상 넉백(글라이드 충격파·메테오)을 갖고 있어 *어차피 만들어야 한다.*

```
서버: 타격 판정 시 대상 몬스터에 ApplySkillMovement를 넉백 파라미터로 적용
      (dir = 모드별 서버 계산, distance/duration/ease-out) → 위치 권위 갱신
패킷: SkillDamageNtf에 넉백 필드 추가
      (knock_dir_x/z, knock_distance, knock_duration_ms) — 데미지와 같은 순간이라 한 패킷에
클라: 수신 → 히트플래시 + hitstop + 넉백을 서버와 "동일 ease-out"으로 로컬 보간
      (캐스터 이동 동기화와 동일 메커니즘)
```
→ 한 패킷으로 데미지·넉백·연출이 한 순간에 동기화. 캐스터 이동(`CastNtf move_distance`)과 같은 패턴.

**추가 데이터 컬럼:** `KnockbackDistance`, `KnockbackDurationMs`, `KnockbackDirMode` (None/SkillDir/RadialFromCaster/RadialFromImpact).

**패킷 확장 (`skill_packet.proto` — SkillDamageNtf에 필드 추가):**
```proto
// 기존 SkillDamageNtf에 append (데미지와 같은 순간에 발생하므로 별도 패킷 불필요)
float  knock_dir_x      = 7;
float  knock_dir_z      = 8;
double knock_distance   = 9;   // 0 이면 넉백 없음
int32  knock_duration_ms = 10; // 0 이면 즉시 스냅
```
클라는 이 필드가 0이 아니면 피격 연출(flash/hitstop/스케일팝)과 **동시에** `f=1-(1-t)^2`로 넉백 보간을 시작한다(캐스터 이동 동기화와 동일 코드 경로 재사용).

## C. 히트플래시 · 기타 juice (전부 클라 전용)

- **히트플래시 (3D) — 머티리얼 인스턴스 빨강 틴트(채택):** 대상 렌더러 머티리얼을 **몬스터당 1회 인스턴스화**해 `_BaseColor`(폴백 `_Color`)를 **원색→빨강으로 강도 보간**했다 부드럽게 복원. 강도를 매 프레임 감쇠하고 재타격 시 1로 리셋 → **연타에도 깜빡이지 않고 빨갛게 유지**. 텍스처 보존(베이스컬러가 텍스처에 곱해짐).
  - *왜 MPB 가 아닌가(중요):* 몬스터 아트가 **커스텀 SRP Batcher 셰이더**라, `MaterialPropertyBlock`으로 `_BaseColor` 하나만 덮어쓰면 나머지 per-material CBUFFER 값이 깨져 **화면이 어둡게 렌더**된다(MPB↔SRP Batcher 비호환). darkFactor 0.98(=2%만 어둡게)인데도 눈에 띄게 어두워지는 증상으로 확인됨. → 실제 머티리얼 인스턴스를 수정해 CBUFFER 를 온전히 유지.
  - *기각된 시도:* ①단색 흰색 머티리얼 스왑(실루엣 번쩍) — 잦은 타격에 색이 확확 튀고 텍스처 사라짐. ②MPB `_BaseColor` 틴트 — 위 SRP Batcher 비호환으로 어두워짐.
  - *비용/후속:* 피격 몬스터는 인스턴스가 생겨 SRP 배칭에서 빠진다(첫 피격 1회 생성·재사용). 물량 성능이 문제면 **MPB 호환 커스텀 플래시 셰이더**(`_FlashColor`+`_FlashAmount`를 PerRendererData 로)로 전환.
- **스쿼시&스트레치 / 스케일 팝:** 피격 메시를 80ms 동안 `1.0 → 1.12 → 1.0` 튕김. 싸고 효과 큰 juice. 캐스터엔 시전 시 미세 리코일.
- **데미지 텍스트:** 기존 `DamageText` 활용. 팝 스케일 + 상승 페이드, 크리/감쇠 색 구분. **`is_duplicate` 플래그**(10% 감쇠)를 흐린 색/작게 표시.
- **히트스파크/임팩트 VFX:** 접점을 명시해 "어디를 맞혔는지" 또렷하게. `OnHitSkillKey`/`EffectPrefabPath`에 짧고 강한 스파크를 얹는다.
- **스크린셰이크 대안:** 기본 루프엔 X. 궁극기 무게가 필요하면 — 랜덤 흔들림❌ / **방향성 카메라 킥**(임팩트 방향 짧게 1회)⭕ 또는 방사형 비네트 플래시. hierarchy 최상단에만 0.1초 이내.
- **물량 성능:** VFX·데미지텍스트 풀링 필수, 히트플래시는 머티리얼 인스턴스 빨강 틴트(피격 시 SRP 배칭 빠짐 — 물량 부하 시 MPB호환 플래시 셰이더로 전환), 원거리/화면밖 적은 juice 생략(LOD). (hitstop·스케일팝은 대상당 비용이 낮아 개수 캡 불필요 — 3부 물량 예산.)

**구현 스케치 (`HitFlash.cs` + 스케일팝 · 전부 클라 전용):**
```csharp
// 머티리얼 인스턴스를 몬스터당 1회 만들어 _BaseColor 를 빨강으로 보간했다 복원(감쇠).
// MPB 가 아니라 인스턴스 → 커스텀 SRP 셰이더 CBUFFER 가 온전(어두워짐 버그 없음), 텍스처 보존.
public class HitFlash : MonoBehaviour {
    const float Fade = 0.12f, Strength = 0.75f;
    static readonly Color Hit = new Color(1f, 0.2f, 0.15f);
    static readonly int BaseColor = Shader.PropertyToID("_BaseColor");
    Material[] mats; Color[] orig; float k; bool on, cached;     // (실제 코드는 HasProperty/_Color 폴백)
    public static void Trigger(MonsterObject m){
        var hf = m.GetComponent<HitFlash>() ?? m.gameObject.AddComponent<HitFlash>();
        if(!hf.cache()) return; hf.k = 1f; hf.on = true;         // 겹치면 강도 1로 리셋
    }
    bool cache(){
        if(cached) return mats.Length>0; cached=true;
        var list=new List<Material>(); var oc=new List<Color>();
        foreach(var r in GetComponentsInChildren<Renderer>())
            foreach(var mat in r.materials){ list.Add(mat); oc.Add(mat.GetColor(BaseColor)); }  // r.materials = 인스턴스화
        mats=list.ToArray(); orig=oc.ToArray(); return mats.Length>0;
    }
    void Update(){
        if(!on) return; k -= Time.unscaledDeltaTime/Fade; bool done = k<=0f; float t = done?0f:k;
        for(int i=0;i<mats.Length;i++){ var c=Color.Lerp(orig[i], Hit, t*Strength); c.a=orig[i].a; mats[i].SetColor(BaseColor,c); }
        if(done) on=false;
    }
}

IEnumerator ScalePop(Transform tr){                       // 80ms 동안 1.0→1.12→1.0
    float d = 0.08f, e = 0; Vector3 b = tr.localScale;
    while(e < d){ e += Time.deltaTime; tr.localScale = b * (1f + 0.12f*Mathf.Sin(e/d*Mathf.PI)); yield return null; }
    tr.localScale = b;
}
```

**오케스트레이션 — 모두 `SkillDamageNtf` 1개에서 분기 (서버 변경 0):**
```csharp
void OnSkillDamageNtf(Monster m, int dmg, bool isDup, bool dead, KnockInfo k){
    HitFlash.Trigger(m);                                          // 흰색 스왑(static)
    HitStop.Trigger(m, dead ? 90 : isDup ? 25 : 40);  // ms
    ScalePop.Play(m);
    SpawnDamageText(dmg, isDup, dead);                                // is_duplicate=흐린색/작게
    if(k.distance > 0) m.StartKnockback(k.dir, k.distance, k.durMs);  // 넉백 필드 있으면
}
```
→ 히트플래시·hitstop·스케일팝·데미지텍스트가 **적중 1프레임에 동시 발화**(0부 "동기화 인과 피드백" 원리 실현). ①②③단계가 전부 이 한 함수에 모인다.

## D. 청각 위계 (Audio Clarity) — 시각이 포화돼도 청각이 구해준다

**원리(LoL):** 사운드가 타격감의 절반 이상이고, 시각이 포화되는 물량 난전에서 청각이 read를 보강한다. 히오스의 실패가 바로 **청각 위계 부재**(동시다발 사운드가 한 덩어리로 뭉개짐)다. 우리 물량 hack&slash는 구조적으로 이 위험에 노출돼 있어 — 시각 juice뿐 아니라 **청각도 위계 + 예산 관리**가 필수다.

채널은 4-1 사운드 매핑과 동일 시점(Cast / Shoot / **Target Hit(적중음)** / Loop). 적중음은 `SkillDamageNtf` 수신 즉시 **0지연** 재생이 핵심.

**물량에서 적중음이 뭉개지는 문제 — 4해법:** (1·3·4 ✅ `SfxPlayer` 구현, 2 후속)
1. **피치 변주 ✅** — 재생마다 ±8% 랜덤 피치(`SfxPlayer`). 같은 샘플도 기관총처럼 안 들린다.
2. **라운드로빈 ⬜** — 단순화를 위해 1차에는 스킬당 클립 1개 + 피치만 사용. 반복감이 거슬리면 변형 풀(원소별 ~12종 순환)로 확장.
3. **Voice limiting ✅** — `SfxPlayer`가 AudioSource 풀(16개)을 라운드로빈, 가득 차면 가장 오래된 소스를 가로채 동시 발성을 풀 크기로 캡.
4. **뭉친 타격은 대표 1회 + 약간 크게 ✅** — 같은 클립이 짧은 윈도우(`k_coalesceWindowMs`≈70ms) 내 또 적중하면 새 보이스를 만들지 않고 **이미 울리는 그 소리의 볼륨만 한 단계씩 키운다**(`k_clusterAddVolume`, 상한 `k_clusterMaxVolume`). 동시 적중음 겹침(위상 간섭·음량 합산 → "피치 올라간 듯한 거친 소리")을 피하면서도 많이 맞을수록 한 방이 묵직해진다. 첫 적중은 0지연으로 즉시 재생.

**위계(hierarchy tier로 음량·무게 차등):**
- 기본기 적중음은 짧고 가벼운 트랜지언트, 궁극기(블레이즈·메테오) 착탄음만 저역 강조 + 크게.
- **주파수 분리** — 원소별로 대역을 나눠(fire=중저역 "쿵", ice=고역 "챙", electric=고역 트랜지언트 "짝") 동시에 나도 서로 안 묻힌다.
- **Ducking(선택)** — 궁극기 착탄 순간 다른 효과음을 수십 ms 살짝 눌러 한 방을 또렷하게. 기본 루프엔 안 씀(과하면 답답).

**데이터화:** 4-1의 `SfxHitKey` 등에서, 변주는 키 1개가 "변형 N개 묶음"을 가리키게 하면 코드 분기 없이 라운드로빈. voice limiting 캡은 전역 상수.

> 검증: 물량 50마리 동시 타격을 녹음해 "한 덩어리 노이즈"가 아니라 개별 타격으로 들리는가. 궁극기 착탄음이 기본기 위로 또렷이 솟는가.

## E. 카메라 킥 (궁극기 한정) — 글로벌 셰이크의 안전한 대체

**원리:** 랜덤 화면 흔들림은 탑다운에서 전장 정보를 파괴한다(0부·LoL). 대신 **방향성 1회 킥** — 임팩트 방향으로 카메라를 짧게 한 번 밀었다 ease-out으로 복귀. "흔든다"가 아니라 "충격이 카메라를 한 번 친다".

**적용 대상: hierarchy 최상단만**(블레이즈·메테오 착탄). 기본기엔 절대 안 쓴다. 동시에 여러 번 발동돼도 1회로 합치고 캡(궁극기 난사 시 멀미 방지).

**파라미터(탑다운 기준):**
- **방향** — 임팩트의 수평 방향(월드 X-Z)을 카메라 rig pivot 오프셋으로. 위에서 내려보므로 위치 오프셋으로 충분.
- **크기** — 작게. pivot 오프셋 0.3~0.6유닛(또는 화면 높이의 1~2%). **회전 킥은 탑다운에서 어지러우니 위치 오프셋만, 회전 X.**
- **시간** — 전체 120~180ms. 어택(밀림) ~30ms, 복귀 ease-out 나머지.
- **커브** — 복귀에 우리 `f=1-(1-t)^2` 재사용(빠르게 갔다 부드럽게 복귀). 일관성 유지.

**탑다운 적용:** 실제 카메라 Transform이 아니라 **카메라 rig의 pivot/follow target에 오프셋을 가산·복원**한다(추적 로직과 분리). 그래야 캐릭터 추적과 안 싸운다.

**절대 금지 재확인:** `Time.timeScale` · 랜덤 셰이크 · 매 타격 셰이크. 전부 0부 원리 위반.

**구현 스케치 (`CameraKick.cs`, 클라 전용 · 카메라 rig에 부착):**
```csharp
public class CameraKick : MonoBehaviour {
    Vector3 offset; float t, dur;
    public void Kick(Vector3 dirWorld, float magnitude, float durationMs){
        Vector3 k = dirWorld.normalized * magnitude;          // 임팩트 수평 방향
        if(k.magnitude > offset.magnitude){ offset = k; t = 0; dur = durationMs/1000f; } // 동시 다발은 큰 쪽으로 합침
    }
    void LateUpdate(){                                          // 추적(follow) 이후 오프셋만 가산
        if(dur <= 0) return;
        t += Time.deltaTime;
        float p = Mathf.Clamp01(t/dur);
        float f = 1f - (1f-p)*(1f-p);                          // ease-out 복귀
        transform.position += Vector3.Lerp(offset, Vector3.zero, f);
        if(p >= 1f){ offset = Vector3.zero; dur = 0; }
    }
}
```
호출: 궁극기 착탄 Area 틱 또는 `SkillDamageNtf`(hierarchy=상 스킬)에서 1회. 데이터: 스킬에 `CameraKickMag`(0=없음) 클라 전용 컬럼 1개면 충분.

## F. 처치/사망 피드백 — 물량 처치를 안 지루하게

**원리(D4 skill-driven death):** 무엇으로 죽였느냐로 시체 연출이 달라져 물량 처치가 작업처럼 안 느껴진다. 우리는 경량판으로 — 죽는 순간 채널을 한 단계 키워 "쓸어담는 쾌감"을 준다.

**훅: 서버 변경 0.** `SkillDamageNtf.is_dead`가 이미 있다 → 오케스트레이션에서 분기(2부 C에 `dead ? 90` hitstop이 이미 반영됨).

**사망 시 추가 발화(클라 전용):**
- **더 긴 hitstop** — 처치 80~100ms(일반 40보다 길게). "마지막 한 방"의 무게.
- **디졸브/페이드 아웃** — 즉시 사라지지 말고 0.3~0.5초 디졸브(셰이더 `_DissolveAmount`)나 가라앉기. 펑펑 사라지면 물량에서 시각 위계가 붕괴 → 빠르게, 하지만 0프레임은 X.
- **방향성 래그돌(경량)** — 풀 물리 래그돌 대신, 죽인 스킬의 넉백 dir(2부 B `knock_dir`)로 시체를 짧게 밀거나 그 방향으로 쓰러지는 죽음 애니 1종. D4 "방향성" 손맛의 저비용 이식.
- **처치 VFX** — 작은 원소별 디스폰 퍼프(불=재, 얼음=파편). `EffectPrefabPath`와 별개 경량 prefab 1개.

**skill-driven death 경량판:** 풀 분기는 과하다. **원소 1축만** — 마지막 타격 스킬 원소로 디졸브 색·퍼프만 바꿈(fire=타들어감, ice=얼어 깨짐). 스킬마다 시체 클립을 만들지 않는다.

**물량 주의:** 처치가 한 프레임에 수십 건(전격방출 광역) → 디졸브·퍼프도 **캡 + LOD**(3부 정책). 화면밖 처치는 즉시 디스폰(연출 생략). 처치 hitstop도 동시 캡에 포함.

> **서버 경계(중요):** 디스폰 권위·보상은 서버(스킬시스템_정리 10절 "사망 처리"). 클라는 `is_dead`를 받으면 **연출만** 하고, 실제 오브젝트 제거는 서버 디스폰 패킷 기준. 연출(0.3~0.5초)과 서버 디스폰 타이밍을 분리해야 한다 — 서버 디스폰 신호에 연출을 시작하거나, 연출 종료 시점을 서버 디스폰에 맞춘다. (이 순서가 어긋나면 "죽었는데 안 사라짐" / "연출 전에 사라짐" 버그)

| **넉백** | **서버 권위** + 클라 예측 | `ApplySkillMovement`(ease-out), `SkillDamageNtf` | 넉백 컬럼 3개 + 패킷 필드 |
| **처치/사망 피드백** | 클라 전용(연출) + 서버(디스폰 권위) | `SkillDamageNtf.is_dead`, 넉백 dir | 디졸브 셰이더, 원소별 퍼프 |
| **카메라 킥 (궁극기)** | 클라 전용 | 카메라 rig, `f=1-(1-t)^2` | `CameraKickMag` 컬럼 1개 |
| **선동작/follow-through** | 클라(애니) | `CastDelayMs`, CastAnim | 미세 anticipation 클립 |

## 작업 우선순위 (가성비 순 = 작업 순서)

> **재검토:** 원래 리스트가 시각 편향이라 **적중음을 1차 웨이브로 승격**한다. 문서 스스로 "사운드가 타격감의 절반 이상"(1부 1절)이라 했는데 우선순위에선 빠져 있었다. 적중음도 클라 전용·패킷 0이라 히트플래시와 **같은 비용·같은 훅**(`SkillDamageNtf`).

1. **히트플래시 + 히트스파크 + 적중음** — 반나절, 패킷 0, 체감 즉각. 전부 `SkillDamageNtf`/`OnHitSkillKey` 한 훅. **시청각 동시 발화**가 0부 원리의 핵심이라 셋을 같이 넣는다.
2. **Hitstop (피격 대상만)** — 클라 전용, 가장 가성비 높은 "묵직함".
3. **데미지텍스트 강화 + 스케일 팝 + 처치 피드백** — 클라 전용. 물량전 가독성·쾌감 + 처치 쾌감(`is_dead` 분기, 서버 변경 0).
4. **넉백 (서버 권위)** — 유일한 서버 작업이지만 어차피 글라이드 충격파·메테오로 필요 → 한 번에 primitive화. `SkillDamageNtf`에 넉백 필드 추가.
5. **폴리시 — 선동작/follow-through + 궁극기 카메라 킥 + 청각 변주**(voice limiting·라운드로빈). hierarchy 최상단부터.

> **가로지르는 제약(단계가 아니라 상시):** 물량 캡/LOD(아래 표)는 1번부터 새 채널을 넣을 때마다 같이 적용한다. juice를 다 만든 뒤 캡을 붙이는 게 아니라, 채널 추가 시점에 캡 슬롯에 등록.

> 문서 철학(Simplicity / Surgical Changes) 준수: 1~3번은 **서버 코드 변경 0, 클라 연출 레이어만 추가**라 리스크 없이 먼저 넣고, 4번 넉백만 서버 primitive로 신중히 설계.

## 노이즈 예산 (히오스화 방지)

- 스킬별 *시각 중요도(hierarchy tier)*를 둔다. 사소한 기본기는 이펙트를 의도적으로 약하게, 궁극기/큰 데미지만 화려하게.
- 화면 흔들림은 hierarchy 최상단(메테오·블레이즈)에만 아껴 쓴다.
- 동시 다발 타격 시 juice 개수 캡 + LOD로 화면·성능 둘 다 보호.

## 물량 예산 (캡/LOD 정책) — 흩어진 "캡"을 한 곳에 수치화

위 노이즈 예산을 **실행 가능한 수치**로 내린다. 문서 곳곳의 "동시 캡"·"LOD 생략"을 한 표로 묶음 — 물량전 프레임을 지키는 유일한 안전장치라 추측이 아니라 명시 수치가 필요하다. (값은 초기 제안, 프로파일링으로 조정)

**거리 LOD (카메라/플레이어 기준 거리별 juice 차등):**

| 구간 | 거리(유닛, 예시) | 발화하는 juice |
|---|---|---|
| 근 | ~15 | 전부 (flash·hitstop·스케일팝·데미지텍스트·적중음·처치 연출) |
| 중 | 15~30 | flash·데미지텍스트·적중음(voice 우선순위 낮음). hitstop·스케일팝 생략 |
| 원 | 30~ | 데미지텍스트만(또는 합산). 화면밖은 전부 생략, 처치는 즉시 디스폰 |

**채널별 동시 발화 캡 (한 프레임/짧은 윈도우) — 인스턴스 비용이 있는 채널만:**

| 채널 | 동시 캡(예시) | 초과 시 |
|---|---|---|
| 히트플래시 | 24 | 가까운 적 우선, 먼 적 생략 |
| 데미지텍스트 | 40 | 합산(겹친 데미지 누적) 또는 풀 고갈 시 생략 |
| 적중음(voice) | 6/샘플 | 가까운 것 우선, 먼 것 버림 |
| 처치 디졸브·퍼프 | 16 | 즉시 디스폰(연출 생략) |
| 카메라 킥 | 1 | 더 큰 쪽으로 합침 |

> **캡은 비용이 드는 채널에만.** Hitstop(`animator.speed` 한 줄)·스케일 팝(`localScale` 곱 한 번)은 대상당 비용이 사실상 0이라 **동시 개수 캡을 두지 않는다** — 캡용 전역 카운터는 begin/end/OnDisable 세 경로에서 완벽히 균형 맞춰야 하고, 한 군데서 새면 전역으로 hitstop 이 멈추는 누수 버그가 되어 보호하는 비용보다 더 위험하다. 먼 적 juice 절감은 거리 LOD(위 표)로 충분. 드로우콜·GPU·GameObject 할당이 드는 VFX·데미지텍스트·오디오만 캡한다.

**캡 초과 시 버리는 우선순위(공통):** 화면밖 > 먼 적 > 방금 안 친 적 순으로 버린다. **가까운 적·방금 친 적·보스/유니크는 항상 유지**(읽혀야 하는 정보).

**풀링 전제:** VFX·데미지텍스트·디졸브는 전부 오브젝트 풀(스킬시스템_정리 10절 "투사체 풀링"과 같은 인프라). 캡은 풀 크기와 연동.

# 4부. 에셋 → 시스템 연결 (Wiring)

준비한 에셋(캐릭터·애니·VFX·SFX)을 **새 시스템 없이** 기존 데이터 컬럼/훅에 꽂는 단계. 핵심 원칙: *layered 에셋의 각 레이어 = 우리 페이즈/이벤트와 1:1*.

## 4-1. 사운드(layered) 매핑

준비한 SFX 팩이 Cast / Shoot / Target Hit / Loop 로 분리·원소별 정리돼 있으면 그대로 들어맞는다.

| SFX 레이어 | 우리 발생 시점 | 구현 |
|---|---|---|
| **Cast** (시전음) | 시전 시작 (`tryCast`) | ✅ `SfxCast` → SfxPlayer |
| **Shoot** (발동음) | 스킬 발동 = entry 발동(CastDelay 경과) 순간 — **모든 타입**(투사체·장판·이동기), 로컬/원격 공용, entry 1회 | ✅ `SfxShoot` → SfxPlayer |
| **Target Hit** (적중음) | **투사체: 클라 hit 판정 시(`SpawnHitExplosionVisual`, 0지연)** / 장판·즉발: `SkillDamageNtf` ← **타격감 핵심** | ✅ `SfxHit` → SfxPlayer |
| **Loop** (지속음) | entry 페이즈 지속(`areaPhaseDurationSec` = 운석 낙하=FirstTickDelay / 장판=Lifetime) | ✅ `SfxLoop` → `SfxPlayer.PlayLoop` (entry 1회, 종료 시 정지) |

- **원소 일치:** VFX 원소(fire/ice/electric)와 SFX 원소를 맞춰 시청각 동기화.
- **위치 SFX:** v1은 2D 재생(SfxPlayer). mono + 3D 공간화는 후속. 적중음은 0지연 재생(`SkillDamageNtf` 수신 즉시).
- **데이터화(구현):** 스킬데이터에 **`SfxCast` / `SfxShoot` / `SfxHit` / `SfxLoop`** 컬럼(string, client) 추가. 값 = Resources 기준 **클립 1개의 정확한 경로**(예: `Sounds/Ultimate Magic Spells/Spell Casts/Fire Spell - Cast 1`). 빈 값 = 그 슬롯 무음. `SfxPlayer`가 그 클립을 `Resources.Load`·캐시 후 ±피치 변주로 재생(라운드로빈 변형 풀은 단순화를 위해 빼고 피치만으로 반복감 완화). `SfxLoop`(지속음)만 `PlayLoop` 으로 entry 페이즈 지속시간 동안 루프 후 정지.
- **적중음 타이밍(클라 권위 일치):** 투사체 hit 은 클라가 판정하므로(폭발 비주얼을 즉시 spawn), 적중음도 서버 `SkillDamageNtf` 를 기다리지 않고 **그 hit 판정 순간에 0지연 재생**(`SpawnHitExplosionVisual`). 이때 쓰는 건 **source(투사체 본체) 스킬 행의 `SfxHit`** — 투사체 본체 행에 적중음을 둔다(폭발 행 `SfxHit` 는 미사용). 장판·즉발(전격방출·얼음지대 등)은 클라 예측이 없어 그대로 `SkillDamageNtf` 시점에 재생. `onSkillDamageNtf` 는 클라 예측 스킬(투사체 직격 ContactHit + OnHit 폭발)의 적중음을 **중복 재생하지 않게** 건너뛴다.
- **`SfxHitIgnoreMs`(int, client):** **스킬 사용(시전) 후 이 값(ms)이 지나기 전까지는 그 스킬의 `SfxHit` 을 재생하지 않는다.** 즉발 틱 장판처럼 사용 직후 첫 적중이 있는 스킬에서 선행음(시전음·발사음)과 적중음이 겹치는 것을 막는 용도. 스킬 사용 시각은 `tryCast` 에서 `skillKey` 별로 기록(`m_skillUseTime`), 적중음 재생 두 지점(`onSkillDamageNtf` 장판 / `SpawnHitExplosionVisual` 투사체)에서 동일하게 `(now − 사용시각) < SfxHitIgnoreMs` 면 생략. (주로 장판 스킬에 사용.)
- **청각 위계·물량 변주는 2부 D 참조** — 적중음 피치/라운드로빈 변주, voice limiting, 원소별 주파수 분리. 이 매핑표는 "어떤 음을 언제", 2부 D는 "물량에서 안 뭉개지게".

## 4-2. VFX(layered) 매핑

| VFX 레이어 | 우리 컬럼/훅 | 비고 |
|---|---|---|
| **Muzzle/Cast** | 발사 순간 + `CastAnim` 소켓 | 손/무기 본에 부착 |
| **Projectile** | `ProjectilePrefabPath` | 이동은 우리 `Projectile`이 구동(에셋의 투사체 로직 X) |
| **Impact/Explosion** | `OnHitSkillKey` → `EffectPrefabPath` | 직격≠폭발 이미 분리됨 |
| **Area Loop** | 장판 prefab + `AreaVfx`(baseDiameter/baseSize) | 데이터 크기(Radius/ObbWidth)로 스케일 |
| **Telegraph(위치표시)** | `TelegraphPrefabPath` | 시전~임팩트(CastDelay+FirstTickDelay) 표시 후 자동 제거. Radius 로 스케일. (메테오 운석) |
| **Movement** | 글라이드 트레일 / 순간이동 puff | in-place, 코드 이동 위에 얹음 |

- **스케일:** prefab의 `AreaVfx` 기준 크기를 데이터 크기에 맞춰 스케일(이미 구현된 규약).
- **탑다운 가독성 / 노이즈 예산:** 사소한 기본기는 약하게, 궁극기만 화려하게(3부 노이즈 예산).
- **렌더 파이프라인 일치(블로커):** 팩이 URP면 프로젝트도 URP여야 함. 분홍색이면 불일치.

## 4-3. 애니메이션 / Animator 연결

- **Humanoid 리타겟:** 애니 FBX = Humanoid, 캐릭터 모델도 Humanoid(아바타 구성) → 자동 리타겟. (Generic은 비휴머노이드/정확보존용)
- **루트모션 금지(in-place):** 우리는 코드 구동 결정론 이동 → 캐스트·이동기 모두 in-place 클립.
- **규약 파라미터:** `Speed`(이동 블렌드) / `Cast`(트리거) / `CastSpeed`(클립을 ActionLock에 맞춤) / `CastUpper`(상반신) + `UpperBody` AvatarMask.
- **release 프레임 = `CastDelayMs`:** 애니 이벤트 대신 *로직은 데이터(CastDelay)가 결정, 애니는 CastSpeed로 release를 그 시점에 맞춤*(네트워크 결정론 안전).
- **CastClass별:** Stationary=전신+잠금 / Mobile=UpperBody Override / Mobility=전신·잠금없음(강제이동이 제어).
- **상반신 클립은 따로 안 구함** — 일반 휴머노이드 클립에 `UpperBody` 마스크를 씌워 만든다.

## 4-4. 마법사 7스킬 매핑표 (검산용)

| 스킬 | 시전음(Cast) | 투사체/발사 | 적중·폭발 (VFX+Hit SFX) | 루프 | 넉백 모드 | hierarchy |
|---|---|---|---|---|---|---|
| 파이어볼 | Fire Cast | Fire Shoot + projectile VFX | Fire Target Hit + 폭발 VFX(`OnHitSkillKey`) | — | RadialFromImpact(폭발) | 중 |
| 얼음지대 | Ice Cast | — (장판) | Ice Hit(틱) | Ice Loop | — | 중 |
| 전격방출 | Electric Cast | — (캐릭터중심) | Electric Hit(즉발) | — | RadialFromCaster | 중 |
| 글라이드 | (이동기) | 대시 트레일 | 충격파 VFX+Hit | — | RadialFromImpact | 하 |
| 순간이동 | (이동기) | blink puff | — | — | — | 하 |
| 블레이즈 | Fire Cast(선딜) | 빔 VFX | Fire Hit(틱) | 화염지대 Loop | SkillDir | **상**(카메라킥) |
| 메테오 | Fire/Earth Cast(선딜) | 낙하 VFX | 착탄 폭발 + 파편(scatter) | — | RadialFromImpact | **상**(카메라킥) |

# 5부. 구현 로드맵 (어디서부터 시작)

> 인식: 7스킬은 **이미 로직이 서버+클라에서 돈다**(스킬시스템_정리.md). 지금 할 일은 새 시스템이 아니라 **표현 레이어 입히기 + 타격감 juice**. 한꺼번에 7개를 붙이지 말고 **1개를 끝까지(수직 슬라이스) → 복제 → juice 확장** 순서.

## 단계별 (각 단계 검증 체크 포함)

**0단계 — 블로커 먼저 (안 풀면 전부 깨져 보임)**
- 렌더 파이프라인 일치(URP↔URP). → 검증: 데모 VFX가 분홍색 아님.
- Humanoid 리타겟 동작. → 검증: 캐릭터가 idle/walk/run + 시전 모션 1개 재생.

**1단계 — 기반: 캐릭터 + Animator 규약 배선**
`Speed`/`Cast`/`CastSpeed`/`CastUpper` + UpperBody 레이어. → 검증: 이동 블렌드 + `Cast` 트리거로 시전 모션.

**2단계 — 파이어볼 수직 슬라이스 (모든 서브시스템 1회씩)**
시전 애니(release≈CastDelay) + 투사체 VFX + 폭발 VFX(`OnHitSkillKey`) + 사운드 3종(Cast/Shoot/Hit) + 데미지텍스트(`SkillDamageNtf`). → 검증: 파이어볼 발사 시 보이고 들리는 전체 체인 + 2클라 원격 재현.

**3단계 — 그 슬라이스에 타격감 juice (클라 전용, 서버 무관)**
히트플래시 + 히트스파크 + hitstop + 스케일팝 + **처치 피드백**(`is_dead` 분기) (전부 `SkillDamageNtf` 오케스트레이션). → 검증: 아래 '검증 기준' 표의 동시 발화·적중음 0지연·즉발 유지 충족.

**4단계 — 나머지 6스킬 복제 (대부분 데이터)**
prefab 경로·SFX 키·CastAnim·AreaVfx 스케일만 채움(4부 매핑표). → 검증: 스킬별 동작.

**5단계 — 넉백 (유일한 서버 작업)**
`ApplySkillMovement` 재사용 + 컬럼 3개 + `SkillDamageNtf` 패킷 필드(2부 B). → 검증: 글라이드 충격파/전격방출 넉백 동기화.

**6단계 — 폴리시**
선동작/follow-through, 궁극기 카메라 킥(2부 E), 청각 변주(voice limiting·라운드로빈, 2부 D), 노이즈 예산 tier, 물량 캡/LOD(3부)·풀링.

## 검증 기준 (측정 가능 — "좋아졌다"를 확인하는 법)

문서 철학(goal-driven)에 맞춰 주관적 "손맛 좋다"를 **체크 가능한 기준**으로 내린다. 위 단계별 "검증" 줄은 아래 해당 행으로 판정 — 단계가 끝났다 = 그 행이 합격.

| 기준 | 측정 방법 | 합격선(예시) |
|---|---|---|
| **동시 발화** | 적중 프레임 녹화/프로파일러로 flash·hitstop·적중음·데미지텍스트가 같은 프레임인지 | 모두 ≤1프레임(16ms) 내 |
| **적중음 0지연** | `SkillDamageNtf` 수신 → 재생 사이 지연 | < 1프레임 |
| **물량 프레임 유지** | 몬스터 N마리(예 200) 동시 타격 시 프레임 | 60fps(16.6ms) 유지, 캡/LOD on |
| **청각 비뭉개짐** | 50마리 동시 타격 녹음 → 개별 타격 식별 | 기관총처럼 안 뭉개짐 |
| **넉백 동기화** | 2클라에서 넉백 종료 위치 비교 | 오차 < 0.5유닛 |
| **결정론 이동** | 글라이드/순간이동 서버·클라 경로 | ease-out 동일, 종료 스냅 일치 |
| **위계 보존** | 기본기 vs 궁극기 시청각 무게 | 궁극기가 명확히 더 크고 무거움 |
| **즉발 유지** | 플레이어 입력→반응(hitstop은 피격 대상만) | 플레이어 조작 끊김 0 |

## 역할 분담

- **코드/데이터(스크립트로 제공 가능):** HitFlash·HitStop·ScalePop·DamageText 강화·CameraKick·적중음 변주(피치/라운드로빈/voice limiting)·처치 피드백(디졸브)·넉백 클라 보간(C#) / 넉백 서버 primitive·패킷·컬럼(C++) / 플래시·디졸브 셰이더.
- **에디터 손작업(수동):** FBX 리타겟, Animator Controller 구성, 프리팹을 데이터 컬럼에 드래그, AreaVfx 크기 맞춤, 렌더 파이프라인 설정.

## 가장 먼저 칠 것 (요약)

**0→1단계(블로커+기반)로 "캐릭터가 시전 모션을 내며 파이어볼을 쏘는" 상태를 먼저 만든다.** 그게 보이면 2단계 슬라이스, 그 위에 3단계 juice. 1~3단계는 서버 변경 0이라 리스크 없이 진행되고, 넉백(5단계)만 서버를 건드린다.
