# 더미 클라이언트

## 위치와 실행

- 프로젝트: `Development/Server/DummyClient/DummyClient.csproj`
- 설정: `Development/Server/DummyClient/config.json`
- 실행 시 `Stage.csv`, `Skill.csv`, `Prop.csv`와 서버용 NavMesh를 읽는다.
- 실행 전에 설정의 확률·시간 범위와 Stage/Skill/NavMesh/Portal 데이터 존재 여부를 검사한다. 잘못된 설정이면 접속을 시작하지 않는다.
- 봇별 네트워크 연결은 비동기로 처리하고, `BotManager`가 모든 봇의 상태 머신을 중앙 틱으로 갱신한다.
- 종료 시 `BotManager`가 모든 봇의 현재 연결을 명시적으로 닫는다.
- 더미 계정 DB 초기화/생성 SQL: `Development/Server/Common/DummyAccounts.mysql.sql`

## Stage 행동

- 최초 캐릭터 선택 뒤 마을에 입장하면 `stageProbabilities`의 Stage별 확률로 하나를 선택한다.
  - 100이 선택되면 마을에 머문다.
  - 101 또는 107이 선택되면 해당 Stage로 연결된 실제 포탈 이동을 수행한다.
- 이후 `stageMove.intervalMs`마다 `stageMove.probability` 확률로 Stage 이동을 시도한다.
- 100에서는 현재 Stage를 제외한 `stageProbabilities`를 상대 비율로 적용해 목적지를 고르고, `StageLayout`의 포탈 목적지(`param0`)와 일치하는 실제 포탈을 이용한다.
- 101과 107에서는 포탈을 찾아가지 않고 `StageMoveReq`로 100에 직접 귀환한다. 사망 중에는 Stage 이동 틱을 실행하지 않으므로 부활한 뒤 다음 확률 주기에 다시 시도한다.
- 포탈 이동은 `ObjectVisibilityNtf.prop_spawns`로 받은 런타임 `object_id`와 위치를 저장한 뒤 다음 순서로 처리한다.
  1. `Prop.csv`에서 `Behavior=Portal`인 프랍만 후보로 선택한다.
  2. 기존 NavMesh 이동으로 포탈 상호작용 범위까지 접근한다.
  3. `ObjectInteractReq`를 보낸다.
  4. 서버가 보낸 `StageMoveRes.target_stage_data_key`로 목적지 NavMesh를 로드한다.
  5. `StageLoadCompleteReq/Res`로 입장을 완료한다.

## Stage별 플레이

- Town: 몬스터 탐지와 스킬 사용을 하지 않는다. `town.roamCheckIntervalMs`마다 `town.roamProbability` 확률로만 배회한다.
- Field: 기존 배회·몬스터 탐지·추격·스킬 로테이션을 유지한다.
- 현재 데이터에서 100은 Town이고, 101과 레이드 맵 107은 Field 타입이므로 101/107이 같은 전투 FSM을 사용한다.
- 스킬의 반복 시전 간격은 `skill.useIntervalMsByStage`에서 Stage별로 설정한다. 기본값은 100=0ms(사용 안 함), 101=700ms, 107=2500ms이다.
- 100에서 포탈 이동이 결정되면 현재 전투나 일반 배회를 중단하고 포탈 접근을 우선한다. 101/107의 직접 귀환은 이동 요청을 즉시 전송한다.

## 캐릭터 생성

- 로그인 후 받은 캐릭터 목록이 비어 있을 때만 새 캐릭터를 생성한다.
- `create.jobProbabilities`의 직업별 확률로 직업을 선택하고, `create.appearancePresetIds`에서 외형 프리셋을 균등하게 무작위 선택한다.
- 직업 확률은 0~1 범위이고 전체 합계가 1이어야 한다. 기본값은 Mage(1) 50%, Warrior(2) 50%이다.
- 현재 기본값은 Mage(1)/Warrior(2)와 각 직업이 지원하는 외형 프리셋 0/1이다.
- 캐릭터가 이미 있으면 새로 만들지 않고 목록의 첫 번째 캐릭터를 선택한다.

### DB 계정 초기화

- 로그인 서버에는 회원가입이나 계정 자동 생성 기능이 없으므로 `Accounts`에 더미 계정을 먼저 생성해야 한다.
- `DummyAccounts.mysql.sql`은 `dummy숫자` 형식의 기존 계정을 찾고 GameDB의 `Item`, `Currency`, `Characters`, `AccountCurrency`를 먼저 지운 뒤 AccountDB 계정을 재생성한다.
- 기본 호출은 `p_apply=FALSE`라 삭제하지 않고 대상만 출력한다. 서버와 더미클라를 모두 종료하고 출력 대상을 확인한 다음 `TRUE`로 변경해 실행한다.
- 기본 생성 범위는 `dummy1..dummy20`, 계정 ID `11000001..11000020`, GameDB shard 0이다. 비밀번호는 더미클라 규칙에 맞게 로그인 ID와 같다.
- 기존 계정 JSON에 기본값인 `game_db_index=0` 필드가 생략되어 있어도 shard 0 계정으로 처리한다.
- 캐릭터 행은 SQL로 만들지 않는다. 계정만 만든 뒤 더미클라가 처음 로그인하면 직업과 외형을 무작위로 골라 정상 생성 패킷으로 캐릭터를 만든다.
- 이 스크립트는 AccountDB와 대상 GameDB가 같은 MySQL 인스턴스에 있는 현재 개발 구성을 대상으로 한다. 다른 인스턴스에 분리된 샤드는 각각의 GameDB에서 먼저 정리해야 한다.

## 전투와 생명주기

- 캐릭터 선택 응답의 `JobId`를 저장하고 `skill.skillsByJob`에 설정한 해당 직업의 스킬만 사용한다.
  - Mage(1): `1001`(Fireball), `1003`(IceField), `1008`(FirePillar)
  - Warrior(2): `2001`(NormalAttack), `2002`(Whirlwind), `2003`(HeavyStrike)
- 준비된 다음 스킬의 `Skill.csv` 사거리 정보를 기준으로 접근한다. `MaxRange`가 없는 타겟 지정 스킬은 `skill.range`를 대체값으로 사용한다.
- 시작할 때 설정된 스킬이 `Skill.csv`의 해당 직업 스킬인지 검사하며, 일치하지 않으면 접속을 시작하지 않는다.
- `SkillCastReq` 송신 횟수와 자기 캐릭터의 `SkillCastNtf` 수신 횟수를 각각 요청/수락 통계로 기록한다.
- Fireball 같은 투사체 스킬은 자기 `SkillCastNtf.effect_id`를 받은 뒤 서버와 같은 부채꼴 방향을 계산한다.
  - 각 투사체 경로에서 처음 만나는 가시 몬스터를 예약 적중 대상으로 선택한다.
  - 대상이 없으면 최대사거리 도달 사건으로 예약한다.
  - 비행시간이 지난 투사체들을 `SkillProjectileHitReq` 한 패킷으로 모아 보고한다.
- 자기 `ObjectDeathNtf`를 받으면 이동·전투·포탈 이동과 예약 투사체를 중단한다.
- 서버 자동 리스폰의 `ObjectReviveNtf`를 받으면 위치와 방향을 적용하고 Stage 행동을 재개한다.

## 타임아웃과 통계

- 포탈 탐색·접근 제한시간이 지나면 현재 이동을 취소하고 다음 확률 주기까지 Stage에 머문다.
- 포탈 상호작용 후 `StageMoveRes`가 오지 않거나 `StageLoadCompleteRes`가 오지 않으면 연결 상태가 불확실하므로 연결을 닫고 재접속한다.
- 상태 출력은 스킬 요청/수락, 투사체 hit 보고, 포탈 시도/성공/실패/타임아웃, 101/107 직접 귀환 시도/성공/실패, 사망/부활, 재접속, Stage 로드 타임아웃을 구분한다.
- 네트워크 통계는 로그인 연결에서 Gateway 연결로 교체되거나 재접속해도 실행 시작 이후 누적값을 유지한다.
- 송수신 각각 누적 패킷·애플리케이션 바이트, 최근 출력 구간의 pkt/s·KiB/s, 평균 패킷 크기, 실행 중 최고 rate를 표시한다. TCP/IP 헤더 크기는 포함하지 않는다.
- 최근 출력 구간에서 송수신 빈도가 높은 패킷 타입 3개를 표시한다.
- 전체/시작/접속/로그인/Stage 입장 봇 수와 상세 핸드셰이크 상태, Stage·직업 분포를 구분한다.
- 로그인 연결, 로그인, Gateway 연결·인증, 캐릭터 생성·선택, Stage 로드·이동 latency의 최근 4096개 표본 기준 avg/p95/max를 표시한다.
- 목표/실제 Tick rate, Tick 처리 avg/max와 초과 횟수, 전체 수신 Queue 현재·구간 최대 길이를 표시한다.
- Tick 루프는 고정 주기 타이머를 사용해 Tick 처리 시간이 대기 시간에 누적되지 않으며, 처리가 지연되면 밀린 Tick을 합쳐 다음 주기로 복구한다.
- 더미클라 프로세스 CPU, Working Set, Private Memory, GC Heap, 초당 할당량, Thread 수를 표시한다.
- 오류는 실행 이후 총횟수와 최근 60초 원인별 Top 3을 표시하며, 개별 봇이 복구된 뒤에도 집계 이력은 유지한다.

## 관련 설정

| 설정 | 의미 |
|---|---|
| `stageProbabilities` | 최초 Stage 선택 확률. 합계는 1이며, 마을 출발 시 현재 Stage를 제외하고 상대 비율로 적용 |
| `stageMove.intervalMs` | 포탈 이동 여부를 검사하는 주기 |
| `stageMove.probability` | 검사 주기마다 포탈 이동을 시작할 확률 |
| `stageMove.portalTimeoutMs` | 포탈 탐색과 접근 제한시간 |
| `stageMove.responseTimeoutMs` | 포탈 상호작용 후 `StageMoveRes` 대기 제한시간 |
| `stageMove.loadTimeoutMs` | `StageLoadCompleteRes` 대기 제한시간 |
| `town.roamCheckIntervalMs` | 마을 배회 여부를 검사하는 주기 |
| `town.roamProbability` | 검사 주기마다 마을 배회를 시작할 확률 |
| `create.jobProbabilities` | 신규 캐릭터 생성 시 적용할 직업 ID별 선택 확률. 전체 합계는 1 |
| `create.appearancePresetIds` | 신규 캐릭터 생성 시 무작위로 선택할 외형 프리셋 목록 |
| `skill.skillsByJob` | 직업 ID별 스킬 로테이션 목록 |
| `skill.useIntervalMsByStage` | Stage별 연속 스킬 시전 간격(ms). Town은 0, 전투 Stage는 0보다 커야 함 |
| `skill.range` | 게임데이터에 사거리가 없는 타겟 지정 스킬의 접근 거리 |
