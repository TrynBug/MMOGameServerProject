# 이동·투사체 개선 계획 (2026-07-04 기준)

## 아키텍처 현황 (조사 완료)
- **이동 = 서버 위치 권위**: 클라는 `MoveIntentReq`(목적지 의도)만 송신, 서버 `WaypointMover`가 NavMesh FindPath→waypoint 추종으로 시뮬레이션. 클라 물리는 이동에 관여하지 않음 (투명벽·지형경사로 막기 불가 — 시도했다 폐기)
- **투사체 = 클라 권위**: 클라 `Projectile.cs`(OnTriggerEnter, 캐릭터만 검사) 비행 → `SkillProjectileHitReq`로 hit 보고. 지형 충돌·서버 검증 없음

## 완료된 수정 (GameServer 빌드 성공, 2026-07-04)
1. `StageNavMesh::FindPath` — 목적지 스냅 실패 시 넓은 박스(8,30,8) 재시도 → 절벽/벽 클릭 시 가장 가까운 walkable로 걸어감 (ToS식 UX)
2. `WaypointMover::SetDestination` — **직선 fallback 삭제** → 경로 없으면 Stop. 절벽 등반·벽 관통의 근본 원인이었음 (몬스터 포함)

## 완료된 수정 (클라, 2026-07-05) — 작업 B + 레이어 체계 도입
- **전역 물리 레이어 규약 신설** (`Client/Assets/Scripts/Game/GameLayers.cs` + `ProjectSettings/TagManager.asset`):
  Ground(6)=지형표면·둔덕, Obstacle(7)=정적 차단물(바위/돌담/기둥), Monster(8), Player(9), Projectile(10). 마스크: `ProjectileBlockerMask=Ground|Obstacle`, `GroundClickMask=Ground|Obstacle|Water`.
- **작업 B(클라 투사체 지형 충돌) 완료**: `Projectile.Update` 가 이동 전 이전→현 세그먼트를 `Physics.Raycast(ProjectileBlockerMask, QueryTriggerInteraction.Ignore)` 로 검사 → 벽(둔덕/장애물)을 물면 그 자리에서 소멸 + 적중 비주얼.
- **벽 충돌 서버 보고**: 이미 설계돼 있던 `SkillHitItem.exploded_on_terrain`(field 5) 경로를 클라가 이제 구동한다. `SkillProjectileGroup.ReportBlocked(index, hitX, hitZ)` 가 `exploded_on_terrain=true`+충돌위치로 보고 → 서버 `Stage::OnSkillProjectileHit` 가 그 위치에 OnHit 폭발(AreaEffect)을 발동하고 적중을 판정. 폭발 중심=벽 위치라 벽 너머 딜 없음. (서버·패킷은 기존 구현 그대로, 클라 감지만 채운 것 — 미완성 기능의 완성)
- **레이어 자동 지정**: `StageManager.loadStageMap` 이 맵 인스턴스화 직후 `assignMapPhysicsLayers` 로 Terrain→Ground, 그 외 solid 콜라이더→Obstacle 일괄 지정(모든 맵 자동, 맵 재생성에도 안전). 몬스터 콜라이더는 `MonsterFactory` 가 Monster, 투사체는 `SkillSystem` 이 Projectile 레이어로.
- 몬스터 hit 은 기존 `OnTriggerEnter` 경로 유지(레이어 분리로 추후 Physics 충돌 매트릭스 최적화 여지). `MouseInputHandler` 는 무변경(RaycastAll+컴포넌트 필터라 회귀 없음).

## 완료된 수정 (GameServer 빌드 성공, 2026-07-05) — 작업 A + 직선폴백 정리
- **작업 A(off-mesh 스냅백) 완료**: `WaypointMover::SetDestination` 이 FindPath 실패 시 `trySnapBackOntoNavMesh` 로 대상을 넓은 박스(8/30/8)의 가장 가까운 walkable 위로 끌어온 뒤 1회 재시도. 이미 mesh 위면 no-op(이동거리<0.3유닛) → 그대로 정지(진짜 도달불가). 공유 mover라 **캐릭터·몬스터 공통** 적용. 스냅백은 넓은 박스 반경(8유닛 XZ)으로 이동이 제한돼 안전.
- **직선 fallback은 이미(2026-07-04) 삭제돼 있었음을 확인** — 코드 동작은 Stop인데 주석/문서스트링만 "직선 이동 fallback"으로 남아 있어 오해를 줬음. `WaypointMover`/`Character` 의 스테일 주석 정리 + `logFallback` 파라미터를 `logMoveFailure` 로 개명(의미 명확화).

### C. 서버 투사체/스킬 LoS 검증 (중) ★핵심 — ②③ ✅ 완료 / ① 보류
**완료 (GameServer 빌드 성공, 2026-07-05) — 범위 ②③ (몬스터 AI + 폭발/범위):**
- `StageNavMesh::IsLineOfSight(from,to)` 신규 — `dtNavMeshQuery::raycast`(끝점 전에 벽 만나면 t<1 → 차단). `Stage::HasLineOfSight` 패스스루. fail-open(NavMesh미준비/시작점 off-mesh/쿼리실패 시 가시=true). ⚠ 지표 2D 판정이라 입체지형 부정확.
- **폭발/범위(③)**: `Stage::QueryEnemiesInShape` 에 `requireLineOfSight`(기본 true) 추가 — center→대상 LoS 막히면 제외. shape 판정 통과분에만 raycast(비용 절감). AreaEffect(폭발·얼음지대·블레이즈·전격방출·DoT)와 MonsterProjectile 이 공통으로 이 관문을 쓰므로 한 곳으로 커버.
- **몬스터 AI(②)**: `MonsterFsmAI` 의 `updateChase.inAttackBand` + `updateAttack.needReposition` 에 몬스터→타겟 LoS 게이트 → 벽 너머면 공격 안 하고 접근/재배치(길찾기가 벽을 돌아감). 거리조건 통과 시에만 raycast.
- 한계: NavMesh raycast는 지표 2D(평지형 전용). 원거리 몬스터는 LoS 얻는 위치를 스마트하게 잡진 못함(재배치 목적지가 벽 뒤일 수 있음) — v1 허용.

**보류 (①, 직격 치트방어):** `OnSkillProjectileHit` 직격 처리 전 시전위치→타겟 LoS 검사. 클라 투사체가 이미 벽에서 소멸(작업 B)해 정상 클라는 관통 못 하므로, 모디파이드 클라 방어용 — 핵 검사 정책상 후순위.
