# 이동·위치 동기화 설계서 (현행 구현 기준 / as-built)

> 목표: 디아블로4 수준의 캐릭터 조작감.
> 패러다임: **스냅샷 스트리밍 + 클라 예측 + 원격 보간 + 서버 화해**.
> 본 문서는 *현재 구현된 상태*를 기술한다. (초기 "구현 직전 설계서"에서 실제 구현 중 바뀐 부분을 모두 반영했다. 주요 변경점은 §9 참조.)

## 1. 핵심 개념 모델

### 1.1 권위 (Authority)
- 모든 위치/HP/데미지/CC/사망의 **유일한 진실은 서버**다.
- 클라가 서버로 보내는 것은 **의도(intent)** 와 **후보(candidate)** 뿐. 클라가 보고한 위치/결과는 진실로 채택하지 않는다.
- 예외(C1): 타격은 클라가 후보를 보내고 서버가 권위 검증 후 적용.

### 1.2 세 가지 동기화 메커니즘
1. **예측 (Prediction) — 내 캐릭터.** 입력 즉시 로컬에서 이동/시전 연출. 서버 응답 대기 안 함. (`LocalPlayerMover`)
2. **보간 (Interpolation) — 원격 액터.** 서버 위치 스냅샷 사이를 버퍼 지연을 두고 직선 보간. 버퍼 고갈 시 짧은 외삽. (`SnapshotInterpolator`)
3. **화해 (Reconciliation) — 내 캐릭터.** 서버 권위 위치를 RTT만큼 앞으로 재시뮬한 기대 위치와 예측을 비교 → 오차만 부드럽게 흡수, 큰 어긋남은 스냅. (`PlayerReconciler`)

### 1.3 시간 모델
- 서버 시뮬레이션 tick: **50ms (20Hz)**. `k_updateTickUnitMs = 50`.
- 객체 갱신 주기(적응형 LOD): 캐릭터는 매 tick(50ms). 몬스터는 유휴 `k_monsterUpdateIntervalMs = 500ms`, 타겟 관여 시 `Monster::SetEngagedTick()`으로 **100ms(engaged)** 승격(`MonsterFsmAI`). → **추격 몬스터의 위치는 이미 100ms(10Hz) 단위로만 변한다.**
- 스냅샷 송신: **객체별 가변**(§3.4). 캐릭터는 변화 시 매 tick(20Hz), 몬스터는 위치 cadence 를 10Hz 로 cap(`k_monsterSnapshotIntervalTicks=2`). 단 몬스터는 위 engaged 갱신 때문에 이미 10Hz 라 이 cap 은 현재 coincident(향후 더 빠른 몬스터용 명시적 상한). 보낼 게 없으면 패킷 자체를 안 보낸다(빈 keepalive 없음).
- 보간 재생: 클라는 `NetClock.InterpDelayMs = 150ms` 만큼 과거를 재생(10Hz 몬스터 100ms 간격도 항상 두 점으로 감싸 보간하기 위함).
- 서버는 단조 증가 `server_tick_seq`(uint32, 서버시각 ≈ seq×50ms)를 모든 스냅샷에 싣는다. 클라 입력에는 `input_seq`를 실어 화해 기준으로 쓴다.
- **NetClock 시각 앵커는 SnapshotNtf 와 분리**되어 있다. 서버가 저빈도(`k_timeSyncPeriodTicks=10`, 2Hz)로 `TimeSyncNtf`(`server_tick_seq`만 운반)를 stage 내 전 유저에게 broadcast 하여 NetClock 을 앵커링한다. SnapshotNtf 가 0건(혼자 유휴 등)이어도 시계가 굶지 않는다. onSnapshotNtf 의 `OnServerTick` 호출은 스냅샷이 흐를 때 더 잦은 앵커를 더하는 보너스(단조 가드로 안전).

## 2. 패킷 설계 (현행)

> 신규/변경 패킷만 기술. 나머지(ObjectVisibilityNtf, StatUpdateNtf, HpMpNtf, BuffNtf, ObjectDeathNtf, SkillCastNtf, SkillDamageNtf 등)는 현행 유지.

### 2.1 클라 → 서버

#### MoveIntentReq  (`GAME_PACKET_ID_MOVE_INTENT_REQ = 1001`)
```proto
message MoveIntentReq {
  uint32 input_seq      = 1;   // 클라 단조 증가. 화해 기준.
  uint32 client_time_ms = 2;   // 클라 송신 시각(ms). v2 RTT/되감기용(v1 미사용).
  EMoveIntent intent    = 3;   // MOVE_INTENT_TO / MOVE_INTENT_STOP
  float dest_x = 4; float dest_y = 5; float dest_z = 6;  // intent=TO 일 때 목표점
  float yaw    = 7;            // 바라보는 방향 hint. 권위 아님.
}
enum EMoveIntent { MOVE_INTENT_NONE = 0; MOVE_INTENT_TO = 1; MOVE_INTENT_STOP = 2; }
```
- **위치 필드 없음**(P2). 송신 throttle: **100ms** 주기(`PlayerMoveController.m_sendIntervalSec = 0.1`) + 마우스 업 시 STOP 1회.
- 기존 `MoveDestReq`/`MoveStopReq`/`MoveNtf`는 **제거**됨.

### 2.2 서버 → 클라

#### SnapshotNtf  (`GAME_PACKET_ID_SNAPSHOT_NTF = 1005`)
```proto
message SnapshotNtf {
  uint32 server_tick_seq = 1;   // 단조 증가
  uint32 ack_input_seq   = 2;   // 이 유저의 마지막 처리 input_seq (화해용)
  repeated ActorStateInfo states = 3;  // AOI 내 "due"(변화/플래그/heartbeat) 객체 상태
}
message ActorStateInfo {
  int64   object_id  = 1;
  fixed32 qpos_xz    = 2;   // (qx<<16)|qz  : X,Z 16bit 양자화
  fixed32 qpos_y_yaw = 3;   // (qy<<16)|qyaw: Y 16bit, yaw 16bit
  uint32  flags      = 4;   // bit0 = isMoving, bit1 = isDead
}
```
- spawn/despawn은 **ObjectVisibilityNtf** 담당. SnapshotNtf는 이미 보이는 객체의 transform만 운반.
- `ack_input_seq`는 수신자 본인 입력 처리 진척도. 본인 캐릭터 상태(`object_id == 내 캐릭터`)도 due면 states에 실린다 → 화해 소스.
- **빈 keepalive 미송신**: `states_size() == 0` 이면 그 tick에 그 유저에게 아무것도 보내지 않는다. (NetClock이 로컬 시간으로 자체 전진하므로 굶지 않음 — §4.4)
- **위치/yaw 양자화**(대역폭 절감, 고빈도 패킷이라): float 4개(20B) → `fixed32` 2개(10B). 16bit 양자화.
  - **X/Z 범위는 per-stage 월드 경계**(navmesh 메타)를 쓴다 → 맵에 딱 맞아 클립 불가 + 정밀도 최적(작은 맵 sub-cm). 경계는 `StageLoadCompleteRes`(world_min/max_x/z 필드)로 클라에 1회 전달.
  - **Y 는 고정 범위 [-512,512]**(per-stage Y 경계 없음, 평면 게임이라 변동 작음), yaw 는 [0,360). 범위 초과는 클램프.
  - 인코드 = `Stage.cpp packQPosXZ/packQPosYYaw`, 디코드 = `StageManager.DecodeActorState`. 양쪽 상수/범위 일치 필수.
  - spawn/위치보정(`CharacterSpawnInfo`/`MonsterSpawnInfo`/`MovePosCorrectNtf`)은 **full float 유지**(저빈도·정밀). 양자화 오차(<0.07u)는 보간·화해 데드존(0.3u)이 흡수.

#### TimeSyncNtf  (`GAME_PACKET_ID_TIME_SYNC_NTF = 1006`)
```proto
message TimeSyncNtf {
  uint32 server_tick_seq = 1;   // 현재 서버 tick. 클라 NetClock 앵커.
}
```
- NetClock 재생 시계의 **권위 앵커**. SnapshotNtf 와 **독립**. 서버가 저빈도(`k_timeSyncPeriodTicks=10`, 2Hz)로 stage 내 전 유저에게 broadcast(`Stage::buildAndSendTimeSync` → `PacketSender::SendTimeSyncNtf`).
- 이로써 SnapshotNtf 송신율을 낮추거나 몬스터를 다른 복제 방식으로 바꿔도 시계가 영향받지 않는다(§4.4).

## 3. 서버 설계 (현행)

### 3.1 Stage tick 파이프라인
```
Stage::OnUpdate(deltaMs):
  m_serverTickSeq++;
  1. processSystemMessages()
  2. processUserPackets()          // MoveIntentReq drain → 시뮬 상태 반영
  3. updateCharacters(deltaMs)     // 권위 이동 시뮬 + sector
  4. updateMonsters(deltaMs)       // 권위 AI/이동 시뮬 + sector
  5. OnStageUpdate(deltaMs)
  6. updateSkillEffects(deltaMs)
  6.4 buildAndSendTimeSync()       // 저빈도(2Hz) NetClock 앵커 broadcast (SnapshotNtf 와 독립)
  6.5 buildAndSendSnapshots()      // AOI별 스냅샷 송신
  7. heartbeat
```
- 이동은 더 이상 상태변화 시점에 broadcast 하지 않는다(`MoveNtf`/`broadcastMoveNtf`/`sendMoveNtfToAoi` 전부 제거). 위치는 6.5에서 스트리밍.

### 3.2 입력(의도) 처리 — `Stage::handleMoveIntentReq`
```cpp
pChar->SetLastInputSeq(req.input_seq());
switch (req.intent()) {
  case MOVE_INTENT_TO:
    if (!pChar->IsActionLocked())                 // 시전 액션락 중엔 이동 입력 무시
      pChar->SetDestination(req.dest_x(), req.dest_y(), req.dest_z());
    break;
  case MOVE_INTENT_STOP:
    pChar->StopAt(pChar->GetPosX(), pChar->GetPosY(), pChar->GetPosZ(), req.yaw());  // 서버 현재 위치에서 정지(클라 위치 불신), yaw만 hint 반영
    break;
}
```

### 3.3 공유 이동 컴포넌트 — `WaypointMover`
- **Character 와 Monster 가 공유**한다(이동 시뮬 중복 제거). 대상 `StageObject&`의 위치/yaw를 직접 갱신, 길찾기는 `obj.GetStage()->FindPath`.
- 인터페이스: `SetDestination(obj, x,y,z, logFallback)`, `Stop()`, `Update(obj, deltaMs, moveSpeed) → bool(최종 도달)`, `IsMoving()`.
- 규칙(클라 `LocalPlayerMover`와 동일해야 동기화됨):
  - 한 tick 이동량을 **while 루프로 소모**해 한 프레임에 여러 waypoint 통과.
  - 시작 위치와 거의 같은 **선두 waypoint 스킵**(heading 떨림 방지).
  - **최종 waypoint 스냅 + 정지**(자투리<1tick 버림 → 슬롯 진동 방지).
  - `FindPath` 실패/3점 미만이면 **직선 폴백**([목적지] 한 점). 폴백 로그는 Character=on, Monster=off(잦은 repath 스팸 방지).
- 주체별 차이는 호출자가 흡수: 이동속도(Character=스탯 `MoveSpdTotal`, Monster=고정 `m_moveSpeed`), 스킬 강제이동(Character 전용), repath throttle(Monster 전용 `k_repathDistSq`).

### 3.4 스냅샷 빌더 — `buildAndSendSnapshots`
2-pass 구조:
- **pass1**: 모든 객체에 `EvaluateSnapshotDue(tickSeq, heartbeatTicks, minMoveIntervalTicks)` 1회 호출(여러 관찰자에게 일관된 due 판정). `minMoveIntervalTicks`는 타입별 — 몬스터 `k_monsterSnapshotIntervalTicks=2`(10Hz), 캐릭터 1(20Hz).
- **pass2**: 유저별로 자기 AOI(`ForEachAdjacentSector`, `k_aoiRange=1`)의 **due 객체만** 모아 `SnapshotNtf` 송신. 위치/yaw는 `packQPosXZ`/`packQPosYYaw`로 양자화해 담는다(§2.2, X/Z는 이 stage 월드 경계 기준). `states_size()>0` 일 때만 전송.

`StageObject::EvaluateSnapshotDue` — due 판정:
```
flagTransition = (IsMoving() != 마지막 송신 moving)            // ★즉시 송신(throttle 우회)
movedOrTurned  = (위치 Δ² > 0.0001) || (yaw Δ > 1°)
due = flagTransition
   || (movedOrTurned && tickSeq - 마지막송신tick >= minMoveIntervalTicks)   // 위치 cadence throttle(몬스터 10Hz)
   || (tickSeq - 마지막송신tick >= heartbeatTicks)                          // 유휴 갱신 (k_snapshotIdleHeartbeatTicks = 20 = 1s)
```
- **이동 플래그 전환은 throttle 우회(즉시)**: 같은 자리에서 멈추면(`StopAt(현재위치)`) 위치 변화가 없어 정지 스냅샷이 heartbeat 까지 누락 → 원격에서 "제자리 달리기 후 뒤로 튐". 플래그 전환을 즉시 잡아 해소. (10Hz throttle 은 *위치 변화* cadence 에만 적용.)
- **몬스터 10Hz cap**: 위치/yaw 변화 송신을 2 tick(100ms) 주기로 제한. 단 추격 몬스터는 engaged 갱신(100ms)으로 이미 위치가 10Hz 로만 변하므로(§1.3) cap 은 현재 coincident — 실측상 추가 절감은 없었고, 네트워크 송신율을 AI tick 에서 분리하는 명시적 상한 역할.

### 3.5 권위 이동/전투 (요약)
- `Character::Update`: 액션락 카운트다운 → 스킬 강제이동(`advanceSkillMove`) 우선 → 아니면 `m_mover.Update(*this, dt, 스탯속도)`.
- `Character::ApplySkillMovement(dir, dist, durMs)`: 대시/블링크. `durMs<=0`이면 끝점 스냅(블링크), `>0`이면 ease-out(`f = 1-(1-t)²`) 글라이드. **클라와 동일 공식**.
- `Character::ApplyActionLock(lockMs)`: Stationary 시전 시 서버 권위로 이동 즉시 정지 + lockMs 동안 이동 입력 무시. `Update`에서 카운트다운. (SkillComponent.TryCast가 호출)
- `Monster`: `WaypointMover` + repath throttle + FSM 두뇌(IMonsterAI). `ExecuteSkill`이 `Stage::ApplyEffectDamage`로 권위 데미지 적용. 공격 슬롯 비율 inner 0.55 / outer 0.85, `updateAttack` 이탈 히스테리시스(`k_attackLeaveMargin`).
- `IsMoving()`은 Character/Monster 모두 `m_mover.IsMoving()` 위임(스킬 강제이동은 IsMoving에 포함 안 됨 — 기존 동작 유지). 이 플래그가 스냅샷 flags와 due 판정의 소스.

## 4. 클라이언트 설계 (현행)

이동 관련 책임이 단일 컴포넌트로 분리되어 있다:

| 컴포넌트 | 책임 |
|---|---|
| `MouseInputHandler` | 화면 좌표 → 월드 지면점(raycast + 평면 폴백) |
| `PlayerMoveController` | 입력 → `MoveIntentReq` 송신(throttle 100ms) + 본인 예측 시작/정지 + RTT용 송신 통보 |
| `LocalPlayerMover` | 본인 예측 이동: 목적지/navmesh 경로 추종, 스킬 강제이동, 회전, 이동 잠금 |
| `PlayerReconciler` | 본인 화해: RTT 추정, 입력 리플레이, 오차 데드존/하드스냅/블리딩 |
| `IRemoteMotionDriver` | **원격 재생 추상화**: `Sample(out pos,yaw,moving)`/`Clear()`. 구현체가 자체 타임라인(NetClock 어느 시각을 읽을지) 소유 → 재생 루프는 클럭/보간/예측을 모름. 하위 `ISnapshotMotionDriver`가 `OnSnapshot` 입력 추가 |
| `SnapshotInterpolator` | `ISnapshotMotionDriver` 구현. 원격 보간 버퍼: 과거재생(RenderTime) 보간/외삽/유휴 재개 (PlayerCharacter 원격 + MonsterObject 공용) |
| `NetClock` | 재생 시계(RenderTime = 추정 서버시각 − 보간지연). 앵커는 `TimeSyncNtf`(§4.4) |
| `PlayerCharacter` | 정체성 + 애니메이션 + 원격 재생(facade, `IRemoteMotionDriver` 위임). 본인은 mover/reconciler에 위임 |
| `MonsterObject` | 항상 원격: `IRemoteMotionDriver`로 재생만 (현 구현체 = `SnapshotInterpolator`) |
| `StageManager` | 패킷 라우팅(onSnapshotNtf/onTimeSyncNtf), NetClock.Tick |

### 4.1 내 캐릭터 — 예측 (`LocalPlayerMover`)
- 클릭 시 즉시 `SetDestination`(navmesh waypoint 추종) + `MoveIntentReq(TO, input_seq++)`. 마우스 업 시 `Stop` + `MoveIntentReq(STOP)`.
- 서버 `WaypointMover`와 **동일 규칙**(while-루프 소모, 선두 waypoint 스킵, 최종 스냅+정지)으로 위치가 어긋나지 않음.
- repath는 매 프레임(`k_repathIntervalSec=0`) — 홀드 이동 중 커서 추적으로 heading 연속.

### 4.2 원격 액터 — 보간 (`SnapshotInterpolator`)
- 수신 스냅샷(서버시각, 위치, yaw, moving)을 시계열 버퍼에 쌓고, `NetClock.RenderTimeMs`를 감싸는 두 점을 선형 보간.
- **위치 기반 점프 클리어**: 두 점 사이 거리² > `k_maxJumpSqr(=64, 8u)`면 텔레포트/블링크로 보고 버퍼 클리어(보간하지 않고 스냅).
- **버퍼 고갈 외삽**: RenderTime이 최신 점보다 미래면, **마지막 점이 이동 중일 때만** 마지막 구간 속도로 등속 외삽(최대 `k_maxExtrapMs=200ms`). 정지/유휴(moving=false)는 외삽 안 하고 hold(멈춘 객체가 흘러가지 않게).
- **유휴 재개 재정렬**: 직전 샘플과의 시간 간격이 `k_resumeRebaseGapMs(=200ms)` 초과면(=유휴 후 재개), 직전(정지) 샘플 타임스탬프를 `InterpDelayMs`만큼 과거로 당긴다. 그러면 RenderTime이 재개 구간 시작(u≈0)에서 출발 → **정지 위치에서 부드럽게 가속**(출발 시 짧은 순간이동 방지).

### 4.3 내 캐릭터 — 화해 (`PlayerReconciler`)
초기 설계의 "무replay 블렌드"를 넘어 **RTT 보상 입력 리플레이**로 구현됨:
```
ReconcileTo(authPos, ackSeq):           // 스냅샷의 본인 항목으로 호출
  if (skillMoving) return                // 스킬 강제이동은 서버와 동일 공식 → 보정 생략
  RTT 추정: rtt = EMA(now - 입력송신시각[ackSeq])
  if (dist(현재, authPos) > 3.0) → 하드스냅(SetPosition) ; 큰 desync(텔포/넉백/거부)
  if (ackSeq < 최신 송신 seq) return     // 게이팅: 서버가 아직 최신 의도 미반영 → 보정 생략
  expected = 이동중이면 MoveTowards(authPos, 최신dest, moveSpeed*rtt) else authPos
  err = expected - 현재
  deadzone = 이동중 0.3, 정지중 max(0.3, moveSpeed*0.12)   // 정지 예측선행을 desync로 오인 방지
  m_posError = (|err| > deadzone) ? err : 0
ApplyBleed(매 프레임): pos += posError * (1 - e^(-6·dt)); posError 소진   // 스냅샷율 무관, 부드러움
```
- **이동만 롤백(C3)**: 화해는 *위치*만 건드린다. 스킬 상태 불변.
- 저핑(LAN)에선 오차≈0 → 보정 거의 없음. 고핑에서 선행 보상 효과.

### 4.4 NetClock (gap-tolerant)
- `RenderTimeMs = s_playbackMs`. 매 프레임 `s_playbackMs += dt`로 전진하고, 목표 `estServerNow − InterpDelayMs`를 부드럽게 추종(`diff*0.1`). 목표가 스냅샷 공백 중에도 로컬 시간으로 같이 전진하므로 **빈 keepalive 없이도** 굶거나 리싱크 점프하지 않는다.
- `estServerNow = 마지막 앵커 서버시각 + (now − 그 수신 로컬시각)`. `|diff| > 500ms`면 즉시 정렬(스테이지 이동 등). `InterpDelayMs=150`, `ServerTickIntervalMs=50`.
- **`InterpDelayMs=150`인 이유**: 몬스터가 10Hz(100ms 간격, §1.3)로 오므로, RenderTime이 항상 두 샘플 사이에 들어가 진짜 보간이 되려면 1.5 간격 이상 필요. 100ms면 경계에 걸쳐 외삽 의존(방향전환 오버슈트) → 150ms로 해소. 원격 재생에만 영향(본인 예측/화해 무관), 원격이 50ms 더 과거에 그려지나 시각상 무시 가능.
- **앵커 소스는 `TimeSyncNtf`(2Hz, SnapshotNtf 와 독립).** NetClock 이 로컬시간으로 자체 전진하므로 이 저빈도 앵커로 충분하다. onSnapshotNtf 도 기회주의적으로 앵커를 갱신하지만 정확성은 TimeSyncNtf 가 보장한다 → SnapshotNtf 송신율을 낮추거나 (몬스터 등) 다른 복제 방식으로 바꿔도 시계는 영향 없음.

### 4.5 라우팅 — `StageManager`
```
onTimeSyncNtf:  NetClock.OnServerTick(server_tick_seq)   // 권위 앵커(2Hz, SnapshotNtf 와 독립)

onSnapshotNtf:
  NetClock.OnServerTick(server_tick_seq)                 // 보너스 앵커(스냅샷 흐를 때만, 단조 가드로 안전)
  foreach state:
    DecodeActorState(state) → pos, yaw                   // 양자화 해제(per-stage X/Z 경계 + 고정 Y, §2.2)
    본인(object_id == LocalPlayer) → ReconcileTo(pos, yaw, ack_input_seq)
    원격 캐릭터              → PlayerCharacter.OnSnapshot(...)  // 보간 버퍼 push
    몬스터                  → MonsterObject.OnSnapshot(...)

onStageLoadCompleteRes: 월드 X/Z 경계 저장(DecodeActorState 가 사용)

Update 매 프레임: NetClock.Tick(dt)
```

## 8. 해소된 기존 문제
- 원격 캐릭터 이동속도=0 / 스냅 텔레포트 → 보간으로 해소.
- 정지 시 "뒤로 당김" → 화해 데드존(정지 속도비례) + RTT 보상.
- 정지 후 "제자리 달리기 1초 + 뒤로 튐" → 스냅샷 due에 이동플래그 전환 포함.
- 유휴→출발 시 "앞으로 짧은 순간이동" → 보간 유휴 재개 재정렬.
- 몬스터 제자리 진동 → 최종 waypoint 스냅+정지, FSM 히스테리시스.
- 바깥 링 몬스터 공격 불가 → 공격 슬롯 비율 1.0 미만(0.55/0.85).
- 빈 스냅샷 20Hz keepalive → gap-tolerant NetClock으로 제거.

## 9. 초기 설계 대비 변경점
- **가변 송신율**: `m_snapshotIntervalTicks(이동1/유휴10)` 방식 → **변화/플래그전환/heartbeat(20tick)** 기반 `EvaluateSnapshotDue`. 빈 keepalive 제거.
- **NetClock**: EMA 오프셋 추정 → **gap-tolerant 재생 시계**(로컬 전진 + 목표 추종).
- **화해**: "무replay 블렌드" → **RTT 보상 입력 리플레이 + 데드존 + 오차 블리딩**(원래 v2 항목을 v1에 포함).
- **원격 외삽**: v2 예정 → **v1 구현**(이동 중에만, 200ms 캡).
- **유휴 재개 재정렬**: 신규 추가(초기 설계 없음).
- **컴포넌트 분리**: 클라 `LocalPlayerMover`/`PlayerReconciler`/`SnapshotInterpolator`/`NetClock`, 서버 공유 `WaypointMover`.
- **throttle**: 500ms → 100ms.

### 9.1 대역폭/구조 개선 (2026-06-18)
- **NetClock 시각 분리**: 앵커를 SnapshotNtf piggyback → 전용 `TimeSyncNtf`(2Hz). 동기화 방식/송신율을 바꿔도 시계 불변. (§1.3/§2.2/§4.4)
- **원격 재생 추상화**: `IRemoteMotionDriver`/`ISnapshotMotionDriver` 도입. 재생 루프가 데이터/타임라인을 모름 → 클럭 선택이 드라이버 내부로. (§4 표)
- **ActorStateInfo 양자화**: pos/yaw float 4개(20B) → `fixed32` 2개(10B). X/Z는 per-stage 월드경계(StageLoadCompleteRes 전달), Y 고정. **실측 SnapshotNtf −23%**(9마리 추격). (§2.2)
- **몬스터 10Hz cadence cap** + **InterpDelay 100→150**: 단 추격 몬스터는 engaged tick(100ms)으로 이미 10Hz라 cap 은 추가 절감 없음(coincident). InterpDelay 150 은 10Hz 보간 견고화. (§1.3/§3.4/§4.4)
- **경로 의도 복제 재평가 후 폐기**: P1(스냅샷 스트리밍) 재확인. 별도 `MonsterMoveBatchNtf` 방식을 구현·실측했으나 **추격(이동 다수) 케이스에서 +49%로 더 비쌌고**(긴 Recast 경로를 repath마다 재전송), 이득 구간(유휴)은 이미 저렴 → 트레이드 거꾸로 → 제거. *교훈: 비싼 곳(이동)은 양자화로, 송신율은 AI tick LOD 로 이미 처리됨.*
- **계측 추가**: `packetstats`(패킷 타입별 송신량, `#ifdef _DEBUG`, 2초 덤프) — 위 의사결정을 수치로 검증.

## 10. 남은 작업 (deferred)
- **게임패드(방향) 이동** — 미구현 기능. 마우스(목표점)와 입력/이동 처리가 다름.
- **몬스터 등급별 tick + think/move 분리** — 대규모 몬스터 CPU 절약(스케일 대비).
- ~~송신율 10Hz 하향 + 보간지연 조정~~ — **완료**(§9.1): 양자화 + 몬스터 10Hz(engaged tick) + InterpDelay 150.
- **`object_id` 축소** — 양자화 후 엔트리에서 가장 큰 필드(int64 varint ~9-10B). per-stage 16bit 핸들로 remap 시 player·monster 전 엔트리 절감. id 처리 전반을 건드리는 큰 변경이라 보류(물량 목표 현실화 시 재검토).
- **랙 보상 되감기(위치 이력 링버퍼)** — 고핑/PvP용.
- **풀 입력 리플레이 화해** — 현재 RTT 단발 보상은 구현됨, 정밀 다단 리플레이는 미구현.
- **스킬 시전 서버 검증**(쿨다운/마나/`SkillCastRejectNtf`), **사망/리스폰**, **몬스터 공격 모션 Ntf**.
